## 1. Three pillars of observability

| Pillar | Answers | Tools |
|---|---|---|
| **Logs** | what happened in detail? | structured JSON logs → Loki / ELK / Cloud Logging |
| **Metrics** | how much / how fast / how often? | Micrometer → Prometheus → Grafana |
| **Traces** | where did the time go across services? | Micrometer Tracing + OpenTelemetry → Tempo / Jaeger / Zipkin |

## 2. Distributed tracing

A request through gateway → orders → inventory → payments gets one **trace id**; each hop is a **span**.

```groovy
implementation 'io.micrometer:micrometer-tracing-bridge-otel'
implementation 'io.opentelemetry:opentelemetry-exporter-otlp'
```
```yaml
management:
  tracing:
    sampling:
      probability: 1.0            # 100% in dev; lower in prod
  otlp:
    tracing:
      endpoint: http://tempo:4318/v1/traces
logging:
  pattern:
    level: "%5p [${spring.application.name},%X{traceId},%X{spanId}]"
```
Trace ids propagate automatically over RestClient/WebClient/Feign and Kafka (with observation enabled). The trace id in logs connects logs ↔ traces.

## 3. Metrics with Prometheus & Grafana

```groovy
implementation 'io.micrometer:micrometer-registry-prometheus'
```
`/actuator/prometheus` exposes metrics. Key ones:
- HTTP: `http_server_requests_seconds` (rate, errors, duration percentiles → RED method)
- JVM: heap, GC pauses, threads
- DB pool: `hikaricp_connections_active`, pending
- Kafka: consumer lag
- Business: orders placed, payments failed

**RED** for services: Rate, Errors, Duration. **USE** for resources: Utilization, Saturation, Errors.

## 4. Alerts & SLOs

- SLO example: "99.9% of `POST /orders` succeed within 500 ms over 30 days."
- Alert on symptoms users feel (error rate, latency), not on every CPU spike.
- Error budget: 0.1% of requests may fail; if the budget burns too fast, slow down releases.

## 5. Local observability stack (Compose)

```yaml
services:
  prometheus:
    image: prom/prometheus
    volumes: [./prometheus.yml:/etc/prometheus/prometheus.yml]
    ports: ["9090:9090"]
  grafana:
    image: grafana/grafana
    ports: ["3000:3000"]
  tempo:
    image: grafana/tempo
    command: ["-config.file=/etc/tempo.yaml"]
    volumes: [./tempo.yaml:/etc/tempo.yaml]
  loki:
    image: grafana/loki
```

## 6. 🏁 Month 8 Project: Microservice Shop

### Requirements
1. Services: **gateway**, **catalog**, **orders**, **inventory**, **payments** (mock provider), **notifications**.
2. Each service: own database/schema, Dockerfile, health checks.
3. Sync calls with timeouts, retries, circuit breakers where needed.
4. Async: Kafka events with outbox; place-order **saga** with compensation.
5. Redis cache for catalog; rate limiting at the gateway.
6. JWT validated at the gateway (and/or each service).
7. Observability: correlation/trace ids in logs, Prometheus metrics, a Grafana dashboard (RED + business), traces in Tempo/Jaeger.
8. `docker compose up` starts everything; README with architecture diagram and a demo script.
9. Tests: unit + Testcontainers integration (Kafka + Postgres) for orders and inventory.
