## 1. Containers recap

- **Image**: immutable template (app + runtime + OS libs), built in **layers**.
- **Container**: running instance of an image.
- **Registry**: stores images (Docker Hub, GCR/Artifact Registry, GHCR).

Containers ≠ VMs: they share the host kernel; start in seconds.

## 2. Dockerfile for Spring Boot (multi-stage)

```dockerfile
# build stage
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY gradlew settings.gradle build.gradle ./
COPY gradle gradle
RUN ./gradlew dependencies -q > /dev/null        # cache dependencies layer
COPY src src
RUN ./gradlew bootJar -x test -q

# extract layers for better caching
FROM eclipse-temurin:21-jdk AS layers
WORKDIR /app
COPY --from=build /app/build/libs/*.jar app.jar
RUN java -Djarmode=tools -jar app.jar extract --layers --launcher

# runtime stage
FROM eclipse-temurin:21-jre
RUN useradd --system --uid 1001 app
USER app
WORKDIR /app
COPY --from=layers /app/app/dependencies/ ./
COPY --from=layers /app/app/spring-boot-loader/ ./
COPY --from=layers /app/app/snapshot-dependencies/ ./
COPY --from=layers /app/app/application/ ./
EXPOSE 8080
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75", "org.springframework.boot.loader.launch.JarLauncher"]
```
Best practices:
- Multi-stage → small runtime image (JRE only).
- Non-root user.
- Layering → rebuilds only change the small application layer.
- `.dockerignore` (build/, .git, .idea).
- Pin image versions; scan with `docker scout` / Trivy.

Alternative without Dockerfile: `./gradlew bootBuildImage` (Cloud Native Buildpacks).

## 3. Core commands

```bash
docker build -t shop-orders:1.0 .
docker run -d --name orders -p 8081:8080 -e SPRING_PROFILES_ACTIVE=prod shop-orders:1.0
docker logs -f orders
docker exec -it orders sh
docker ps / docker stop orders / docker rm orders
docker images / docker image prune
docker tag shop-orders:1.0 ghcr.io/me/shop-orders:1.0 && docker push ghcr.io/me/shop-orders:1.0
```

## 4. Docker Compose for the whole system

```yaml
services:
  postgres:
    image: postgres:17-alpine
    environment: { POSTGRES_DB: shop, POSTGRES_USER: shop, POSTGRES_PASSWORD: shop }
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U shop"]
      interval: 5s
      retries: 10

  orders:
    build: ./orders-service
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/shop
      SPRING_DATASOURCE_USERNAME: shop
      SPRING_DATASOURCE_PASSWORD: shop
    depends_on:
      postgres: { condition: service_healthy }
    ports: ["8081:8080"]

  catalog:
    build: ./catalog-service
    ports: ["8082:8080"]

volumes:
  pgdata:
```
```bash
docker compose up -d --build
docker compose logs -f orders
docker compose down -v      # also delete volumes
```
Services reach each other by **service name** (`postgres:5432`) on the compose network.

## 5. Container-friendly Spring Boot

- Config via environment variables (12-factor).
- Logs to stdout (JSON in prod).
- Health endpoints for orchestrators.
- Graceful shutdown: `server.shutdown=graceful`.
- Memory: `-XX:MaxRAMPercentage` respects container limits.
