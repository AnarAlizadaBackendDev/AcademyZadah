> **Goal:** use Apache Kafka for event streaming between services.
> **Duration:** 120 min

## 1. Why messaging?

- **Decoupling**: orders-service publishes `OrderPlaced`; it doesn't know who listens (notifications, analytics, loyalty).
- **Resilience**: consumers can be down; messages wait.
- **Scalability**: many consumers process in parallel.
- **Event streams**: real-time data pipelines (payments monitoring, fraud detection).

## 2. Kafka concepts

```
Producer ──▶ Topic "orders" ──▶ Consumer group "notifications" (2 consumers)
             ├── partition 0: [m0][m1][m2]...    ──▶ consumer A
             ├── partition 1: [m0][m1]...         ──▶ consumer B
             └── partition 2: [m0][m1][m2][m3]... ──▶ consumer A
```
| Concept | Meaning |
|---|---|
| Topic | named stream of records |
| Partition | ordered, append-only log; unit of parallelism |
| Offset | position of a record in a partition |
| Key | records with the same key go to the same partition → **ordering per key** |
| Consumer group | consumers sharing work; each partition → one consumer in the group |
| Retention | records kept for time/size (not deleted on consume!) |
| Replication | copies on several brokers for durability |

Messages are **not removed** when read: different groups read independently; you can replay.

### Producer
```java
public record OrderPlaced(String eventId, Long orderId, Long customerId, BigDecimal total, Instant occurredAt) { }

@Service
class OrderEventsPublisher {
    private final KafkaTemplate<String, OrderPlaced> kafka;

    void publish(OrderPlaced event) {
        kafka.send("orders.placed", event.orderId().toString(), event)     // key = orderId → ordering per order
             .whenComplete((res, ex) -> {
                 if (ex != null) log.error("Publish failed for order {}", event.orderId(), ex);
             });
    }
}
```

### Consumer
```java
@Component
class OrderPlacedListener {
    @KafkaListener(topics = "orders.placed", groupId = "notifications", concurrency = "3")
    void on(OrderPlaced event) {
        notifications.sendOrderConfirmation(event.customerId(), event.orderId());
    }
}
```

## 5. Delivery semantics

| Semantics | Meaning |
|---|---|
| at-most-once | may lose messages |
| **at-least-once** (typical) | may deliver **duplicates** → consumers must be **idempotent** |
| exactly-once | Kafka transactions (within Kafka); end-to-end requires idempotency anyway |

Idempotent consumer:
```java
@Transactional
void on(OrderPlaced e) {
    if (processedEvents.existsById(e.eventId())) return;     // already handled
    notifications.send(...);
    processedEvents.save(new ProcessedEvent(e.eventId()));
}
```

## 6. Errors: retries and dead-letter topics

```java
@Bean
DefaultErrorHandler errorHandler(KafkaTemplate<Object, Object> template) {
    var recoverer = new DeadLetterPublishingRecoverer(template);           // → orders.placed.DLT
    return new DefaultErrorHandler(recoverer, new FixedBackOff(1000L, 3));
}
```
Poison messages go to the DLT after retries instead of blocking the partition.
