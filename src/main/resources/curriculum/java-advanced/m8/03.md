> **Goal:** build microservice infrastructure with Spring Cloud: config, discovery and an API gateway.
> **Duration:** 120 min

## 1. Problems in a microservice landscape

- Where is each service? (IPs change) → **service discovery**
- One entry point for clients, routing, auth, rate limiting → **API gateway**
- Config for 20 services × 3 environments → **centralized config**
- Calls between services with load balancing → **client-side load balancing**

In Kubernetes (month 9), discovery and config are often provided by the platform (Services, ConfigMaps). Spring Cloud is still common in existing systems and on VMs.

## 2. API Gateway: Spring Cloud Gateway

```groovy
implementation 'org.springframework.cloud:spring-cloud-starter-gateway'
```
```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: catalog
          uri: lb://catalog-service           # load-balanced via discovery
          predicates:
            - Path=/api/v1/products/**, /api/v1/categories/**
        - id: orders
          uri: lb://orders-service
          predicates:
            - Path=/api/v1/orders/**
          filters:
            - name: RequestRateLimiter
              args:
                redis-rate-limiter.replenishRate: 10
                redis-rate-limiter.burstCapacity: 20
            - AddRequestHeader=X-Gateway, shop
```
Gateway responsibilities: routing, TLS termination, authentication (validate JWT once), rate limiting, CORS, request logging/correlation ids.

## 3. Service discovery: Eureka

```java
@SpringBootApplication
@EnableEurekaServer
public class DiscoveryServer { ... }
```
Clients:
```yaml
spring.application.name: orders-service
eureka.client.service-url.defaultZone: http://discovery:8761/eureka
```
Services register themselves; others call `http://catalog-service/...` and the load balancer picks an instance.

```java
@Bean
@LoadBalanced
RestClient.Builder lbRestClientBuilder() { return RestClient.builder(); }

RestClient catalog = builder.baseUrl("http://catalog-service").build();
```

## 4. Config Server

```java
@SpringBootApplication
@EnableConfigServer
public class ConfigServer { }
```
```yaml
spring.cloud.config.server.git.uri: https://github.com/me/shop-config
```
```
shop-config/
├── application.yml              shared
├── orders-service.yml
├── orders-service-prod.yml
```
Clients: `spring.config.import: optional:configserver:http://config:8888`.
Refresh at runtime with `/actuator/refresh` or Spring Cloud Bus.

## 5. Inter-service calls with OpenFeign

```java
@FeignClient(name = "catalog-service")
public interface CatalogClient {
    @GetMapping("/api/v1/products/{id}")
    ProductDto get(@PathVariable Long id);
}
```

## 6. Hands-on (Compose)

1. Discovery server (Eureka), config server (local Git folder).
2. Catalog and orders services registered in Eureka; orders calls catalog via `lb://`.
3. Gateway routing both; JWT validated at the gateway and forwarded.
4. Run 2 instances of catalog; observe load balancing.
5. Rate limiting with Redis at the gateway.
