> **Goal:** create threads and understand why concurrent code is hard.
> **Duration:** 120 min

## 1. Process vs thread

- **Process**: a running program with its own memory.
- **Thread**: a path of execution inside a process; threads **share the heap** but each has its own stack.

Why threads? Use multiple CPU cores, keep apps responsive, handle many requests at once (a web server handles each request on a thread).

## 2. Creating threads

```java
// 1. Runnable (preferred)
Runnable task = () -> System.out.println("Running in " + Thread.currentThread().getName());
Thread t1 = new Thread(task, "worker-1");
t1.start();          // start(), NOT run()!

// 2. Extending Thread (less flexible)
class Worker extends Thread {
    @Override public void run() { ... }
}

// 3. Java 21
Thread.ofPlatform().name("p-1").start(task);
Thread.ofVirtual().start(task);
```

`run()` would execute in the **current** thread: no concurrency.

## 3. Thread lifecycle

```
NEW ──start()──▶ RUNNABLE ◀──▶ BLOCKED / WAITING / TIMED_WAITING
                    │
                    ▼
               TERMINATED
```

```java
Thread t = new Thread(() -> sleep(1000));
t.start();
t.join();            // wait until t finishes
t.isAlive();
t.getState();
```
`Thread.sleep(ms)` pauses the current thread. `InterruptedException` must be handled:
```java
try {
    Thread.sleep(500);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();   // restore the flag, don't swallow
    return;
}
```

## 4. Race condition

```java
public class Counter {
    private int count = 0;
    public void increment() { count++; }   // read → add → write: NOT atomic
    public int get() { return count; }
}

Counter c = new Counter();
Runnable r = () -> { for (int i = 0; i < 100_000; i++) c.increment(); };
Thread a = new Thread(r), b = new Thread(r);
a.start(); b.start();
a.join(); b.join();
System.out.println(c.get());   // expected 200000, prints e.g. 137492
```
Two threads read the same value, both add 1, both write: one increment is **lost**.

Race condition = result depends on unpredictable timing. Real-world example: two payment requests reading the same balance at the same time → double spending.

## 5. Visibility problem

```java
private boolean running = true;

void worker() { while (running) { /* work */ } }   // may never stop!
void stop() { running = false; }
```
Each CPU core may cache `running`; the worker might never see the change. Fixed with `volatile` (next lesson).

## 6. Daemon threads and names

```java
Thread t = new Thread(task);
t.setDaemon(true);     // JVM doesn't wait for daemon threads on exit
t.setName("report-generator");   // always name threads: helps in logs and thread dumps
```

Thread dump of a running app: `jcmd <pid> Thread.print` or `jstack <pid>`.

## 7. Hands-on

1. Start 3 named threads printing numbers 1–5 with small sleeps; observe interleaving.
2. Reproduce the counter race condition; run it 5 times and record the results.
3. Simulate a bank account with two threads withdrawing 100 from a balance of 150; show it can go negative.
