## 1. Concurrent collections

Normal collections are **not thread-safe**. Options:

| Need | Use |
|---|---|
| map shared by many threads | `ConcurrentHashMap` |
| list mostly read, rarely written | `CopyOnWriteArrayList` |
| producer–consumer queue | `BlockingQueue` (`ArrayBlockingQueue`, `LinkedBlockingQueue`) |
| sorted concurrent map | `ConcurrentSkipListMap` |

`Collections.synchronizedMap(...)` locks the whole map: slower under contention.

### ConcurrentHashMap atomic operations
```java
ConcurrentHashMap<String, Long> views = new ConcurrentHashMap<>();
views.merge(page, 1L, Long::sum);                         // atomic counter
views.computeIfAbsent(userId, id -> loadProfile(id));     // atomic lazy load
views.putIfAbsent(key, value);
```
❌ `if (!map.containsKey(k)) map.put(k, v);`: check-then-act is a race.

## 2. Atomic variables

Lock-free, based on CPU **compare-and-swap (CAS)**.
```java
AtomicInteger counter = new AtomicInteger();
counter.incrementAndGet();
counter.addAndGet(5);
counter.compareAndSet(10, 0);
counter.updateAndGet(x -> Math.min(x + 1, 100));

LongAdder hits = new LongAdder();     // best for very high contention counters
hits.increment();
hits.sum();

AtomicReference<Config> config = new AtomicReference<>(initial);
config.set(newConfig);
```

## 3. Producer–consumer with BlockingQueue

```java
BlockingQueue<Payment> queue = new ArrayBlockingQueue<>(1000);

Runnable producer = () -> {
    for (Payment p : incoming()) queue.put(p);          // blocks if full (back-pressure)
};
Runnable consumer = () -> {
    while (true) {
        Payment p = queue.take();                       // blocks if empty
        process(p);
    }
};
```
This is the same idea behind message brokers like Kafka (month 8).

## 4. Virtual threads (Java 21)

Platform threads map 1:1 to OS threads (expensive, ~thousands max). **Virtual threads** are lightweight threads managed by the JVM: you can have **millions**.

When a virtual thread blocks on I/O (HTTP call, DB query, sleep), the JVM **unmounts** it from its carrier OS thread, which runs another virtual thread.

```java
try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 10_000).forEach(i ->
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));    // simulate I/O
            return i;
        }));
}   // 10,000 tasks finish in ~1 second
```
```java
Thread.startVirtualThread(() -> handle(request));
Thread.ofVirtual().name("vt-", 0).start(task);
```

### Rules for virtual threads
- ✅ Great for **I/O-bound** work (web requests, DB, HTTP clients).
- ❌ No benefit for CPU-bound computations.
- ❌ Don't pool virtual threads: create one per task.
- ⚠️ Avoid long `synchronized` blocks around I/O (pinning in older JDKs; improved in JDK 24); prefer `ReentrantLock`.
- ⚠️ Limit access to scarce resources (DB connections) with a `Semaphore` or the connection pool, not with thread counts.

Spring Boot 3.2+: `spring.threads.virtual.enabled=true` → every request on a virtual thread.

## 5. Step by step: compare platform vs virtual

```java
static void run(ExecutorService executor, int tasks) throws Exception {
    long start = System.currentTimeMillis();
    try (executor) {
        for (int i = 0; i < tasks; i++) {
            executor.submit(() -> { Thread.sleep(500); return null; });
        }
    }
    System.out.println(tasks + " tasks: " + (System.currentTimeMillis() - start) + " ms");
}

run(Executors.newFixedThreadPool(200), 10_000);          // ~25 s
run(Executors.newVirtualThreadPerTaskExecutor(), 10_000); // ~0.6 s
```
