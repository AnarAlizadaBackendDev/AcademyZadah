> **Goal:** write non-blocking asynchronous pipelines with `CompletableFuture`.
> **Duration:** 120 min

## 1. Problem with Future

`future.get()` **blocks**. Combining several futures ("when A and B are done, do C; if it fails, fallback") is painful.
`CompletableFuture` lets us **compose** asynchronous steps.

## 2. Starting async work

```java
CompletableFuture<Double> rate =
        CompletableFuture.supplyAsync(() -> rateService.usdToAzn());          // common ForkJoinPool

ExecutorService io = Executors.newFixedThreadPool(10);
CompletableFuture<Customer> customer =
        CompletableFuture.supplyAsync(() -> customerService.load(id), io);   // your own pool ✅

CompletableFuture<Void> audit = CompletableFuture.runAsync(() -> auditLog.write(event), io);
```
For I/O work, always pass your own executor (or a virtual-thread executor).

## 3. Transforming and chaining

| Method | Like | Use |
|---|---|---|
| `thenApply(fn)` | `map` | transform the result |
| `thenAccept(consumer)` | | consume the result |
| `thenRun(runnable)` | | run after completion |
| `thenCompose(fn)` | `flatMap` | next step is async too |
| `thenCombine(other, fn)` | | combine two independent futures |

```java
CompletableFuture<String> greeting = supplyAsync(() -> loadUser(42))
        .thenApply(User::name)
        .thenApply(name -> "Hello, " + name);

CompletableFuture<Order> order = supplyAsync(() -> loadCart(userId))
        .thenCompose(cart -> supplyAsync(() -> createOrder(cart)));   // avoids CF<CF<Order>>

CompletableFuture<Double> totalInAzn = supplyAsync(() -> cartTotalUsd())
        .thenCombine(supplyAsync(() -> usdRate()), (usd, rate) -> usd * rate);
```

## 4. Waiting for many

```java
CompletableFuture<Account> acc = supplyAsync(() -> accounts.load(id), io);
CompletableFuture<List<Card>> cards = supplyAsync(() -> cardsService.load(id), io);
CompletableFuture<List<Loan>> loans = supplyAsync(() -> loanService.load(id), io);

CompletableFuture.allOf(acc, cards, loans).join();       // wait for all
Dashboard d = new Dashboard(acc.join(), cards.join(), loans.join());

CompletableFuture<Object> first = CompletableFuture.anyOf(primary, backup);
```
`join()` is like `get()` but throws unchecked `CompletionException`.

## 5. Error handling

```java
supplyAsync(() -> riskyCall())
    .exceptionally(ex -> {                       // fallback value
        log.warn("Call failed: {}", ex.getMessage());
        return defaultValue;
    });

supplyAsync(() -> riskyCall())
    .handle((result, ex) -> ex == null ? result : fallback);   // both cases

supplyAsync(() -> riskyCall())
    .whenComplete((result, ex) -> metrics.record(ex == null));  // side effect, doesn't change result
```

## 6. Timeouts (Java 9+)

```java
supplyAsync(() -> slowService.call(), io)
    .orTimeout(2, TimeUnit.SECONDS)                       // fails with TimeoutException
    .exceptionally(ex -> cachedValue());

supplyAsync(() -> slowService.call(), io)
    .completeOnTimeout(cachedValue(), 2, TimeUnit.SECONDS);   // default value on timeout
```

## 7. Step by step: customer dashboard aggregator

```java
public Dashboard load(long customerId) {
    var profile = supplyAsync(() -> profileClient.get(customerId), io)
            .orTimeout(1, SECONDS);
    var balance = supplyAsync(() -> accountClient.balance(customerId), io)
            .orTimeout(1, SECONDS);
    var offers = supplyAsync(() -> offerClient.offers(customerId), io)
            .completeOnTimeout(List.of(), 500, MILLISECONDS);   // optional data

    return profile.thenCombine(balance, (p, b) -> new Dashboard(p, b, List.of()))
                  .thenCombine(offers, (d, o) -> d.withOffers(o))
                  .join();
}
```
Sequential: 1s + 1s + 0.5s; parallel: max(1s, 1s, 0.5s).

## 8. Common mistakes

- ❌ Calling `.get()`/`.join()` right after `supplyAsync` (= synchronous again).
- ❌ Using the common pool for blocking I/O.
- ❌ Forgetting error handling: exceptions disappear silently if nobody joins.
- ❌ `thenApply` returning a CompletableFuture (use `thenCompose`).
