## 2. Sealed classes and interfaces (Java 17)

Restrict which classes can extend a type: a **closed hierarchy**.

```java
public sealed interface PaymentMethod permits Card, BankTransfer, Qr { }
public record Card(String maskedPan) implements PaymentMethod { }
public record BankTransfer(String iban) implements PaymentMethod { }
public record Qr(String merchantId) implements PaymentMethod { }
```
The compiler knows **all** possible subtypes → exhaustive switches.

## 3. Pattern matching

### instanceof
```java
if (obj instanceof Card c && c.maskedPan().startsWith("4")) { ... }
```

### switch with patterns (Java 21)
```java
double fee(PaymentMethod method, double amount) {
    return switch (method) {
        case Card c -> amount * 0.015;
        case BankTransfer t -> 1.0;
        case Qr q -> 0;
    };                                    // no default needed: sealed + exhaustive
}
```

### Guards
```java
String risk(Transaction tx) {
    return switch (tx) {
        case Transaction t when t.amount() > 10_000 -> "HIGH";
        case Transaction t when t.country().equals("AZ") -> "LOW";
        default -> "MEDIUM";
    };
}
```

## 5. Modeling with sealed types: a Result type

```java
public sealed interface TransferResult {
    record Success(String transactionId) implements TransferResult { }
    record Rejected(String reason) implements TransferResult { }
    record Failed(Exception error) implements TransferResult { }
}

String message = switch (result) {
    case TransferResult.Success s -> "Done: " + s.transactionId();
    case TransferResult.Rejected r -> "Rejected: " + r.reason();
    case TransferResult.Failed f -> "Error: " + f.error().getMessage();
};
```
Adding a new subtype breaks compilation of every switch that doesn't handle it, which is exactly what we want.

## 6. 🏁 Month 1 Project: Concurrent Log Analyzer

### Requirements
1. Input: a folder with many large log files (generator script provided by the teacher, ~1 GB total).
2. Log line format: `2026-03-01T10:15:30Z LEVEL service=payments latencyMs=123 msg="..."`.
3. Parse lines into a **record**; level as a **sealed** hierarchy or enum; use pattern matching where natural.
4. Process files in parallel (virtual threads or a fixed pool: justify your choice).
5. Aggregate with concurrent structures:
   - count per level and per service
   - p50 / p95 / p99 latency per service
   - top 10 most frequent error messages
   - errors per minute timeline
6. Print a report and write it to `report.json`.
7. Compare the time: single-threaded vs parallel; include results in the README.
8. Tests for the parser and the aggregations.
