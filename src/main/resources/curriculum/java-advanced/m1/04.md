> **Goal:** make concurrent code correct with synchronization, volatile and locks, and avoid deadlocks.
> **Duration:** 120 min

## 1. `synchronized`

Only one thread at a time can execute a synchronized block **on the same lock (monitor)**.

```java
public class Counter {
    private int count;

    public synchronized void increment() { count++; }   // lock = this
    public synchronized int get() { return count; }
}

public class Account {
    private final Object lock = new Object();
    private double balance;

    public void withdraw(double amount) {
        synchronized (lock) {                           // smaller critical section
            if (balance < amount) throw new IllegalStateException("Insufficient funds");
            balance -= amount;
        }
    }
}
```
`synchronized` gives **mutual exclusion** and **visibility** (changes are visible to the next thread taking the lock).

## 2. `volatile`

Guarantees **visibility** (no caching), but **not atomicity**.

```java
private volatile boolean running = true;   // ✅ stop flag
private volatile int count;                // ❌ count++ still not atomic
```
Use volatile for simple flags written by one thread and read by others.

## 3. Happens-before (in one sentence)

Everything a thread did **before** releasing a lock / writing a volatile is visible to a thread that **afterwards** acquires the same lock / reads that volatile.

## 4. Explicit locks

```java
import java.util.concurrent.locks.*;

private final ReentrantLock lock = new ReentrantLock();

public void transfer(double amount) {
    lock.lock();
    try {
        // critical section
    } finally {
        lock.unlock();          // ALWAYS in finally
    }
}

if (lock.tryLock(500, TimeUnit.MILLISECONDS)) { ... }   // don't wait forever
```

`ReadWriteLock`: many readers or one writer:
```java
private final ReadWriteLock rw = new ReentrantReadWriteLock();
public double rate(String currency) {
    rw.readLock().lock();
    try { return rates.get(currency); } finally { rw.readLock().unlock(); }
}
public void update(Map<String, Double> newRates) {
    rw.writeLock().lock();
    try { rates.putAll(newRates); } finally { rw.writeLock().unlock(); }
}
```

## 5. Deadlock

```java
void transfer(Account from, Account to, double amount) {
    synchronized (from) {
        synchronized (to) {            // thread 1: A→B locks A then B
            from.withdraw(amount);     // thread 2: B→A locks B then A → DEADLOCK
            to.deposit(amount);
        }
    }
}
```
Four conditions: mutual exclusion, hold-and-wait, no preemption, **circular wait**.

### Fix: consistent lock ordering
```java
void transfer(Account from, Account to, double amount) {
    Account first = from.getId() < to.getId() ? from : to;
    Account second = first == from ? to : from;
    synchronized (first) {
        synchronized (second) {
            from.withdraw(amount);
            to.deposit(amount);
        }
    }
}
```
Other fixes: `tryLock` with timeout, a single coarser lock, or (in real systems) database transactions.

Detect: thread dump shows `Found one Java-level deadlock`.

## 6. wait / notify (legacy) → use higher-level tools

`wait()`/`notify()` exist but are error-prone. Prefer `BlockingQueue`, `CountDownLatch`, `Semaphore` (next lessons).

```java
CountDownLatch ready = new CountDownLatch(3);
// each worker: ready.countDown();
ready.await();   // main waits until all 3 are done

Semaphore permits = new Semaphore(5);   // max 5 concurrent calls to an external API
permits.acquire();
try { callApi(); } finally { permits.release(); }
```

## 7. Hands-on

1. Fix the counter race three ways: `synchronized`, `ReentrantLock`, `AtomicInteger`; measure the time of each with 4 threads × 1M increments.
2. Create a deadlock with two accounts and two threads; take a thread dump with `jcmd`; fix it with lock ordering.
3. Limit parallel calls to a fake external service to 3 with a `Semaphore`.
