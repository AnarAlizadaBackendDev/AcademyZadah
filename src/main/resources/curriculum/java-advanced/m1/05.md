> **Goal:** run tasks efficiently with thread pools, `Callable` and `Future`.
> **Duration:** 120 min

## 1. Why not `new Thread()` everywhere?

- Creating platform threads is expensive (~1 MB stack each).
- Unlimited threads → memory exhaustion and context-switch overhead.
- No easy way to get results or handle errors.

**Thread pools** reuse a fixed set of threads for many tasks.

## 2. ExecutorService

```java
ExecutorService pool = Executors.newFixedThreadPool(4);

pool.submit(() -> System.out.println("task on " + Thread.currentThread().getName()));

pool.shutdown();                                  // no new tasks; finish queued ones
if (!pool.awaitTermination(30, TimeUnit.SECONDS)) {
    pool.shutdownNow();                           // interrupt running tasks
}
```
Java 19+: `ExecutorService` is `AutoCloseable`:
```java
try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
    ...
}   // waits for tasks to finish
```

| Factory | Behaviour |
|---|---|
| `newFixedThreadPool(n)` | n threads, unbounded queue |
| `newCachedThreadPool()` | grows as needed (careful!) |
| `newSingleThreadExecutor()` | one thread, tasks in order |
| `newScheduledThreadPool(n)` | delayed/periodic tasks |
| `newVirtualThreadPerTaskExecutor()` | one virtual thread per task (Java 21) |

## 3. Callable and Future

`Runnable` returns nothing; `Callable<T>` returns a value and can throw exceptions.

```java
Callable<Double> fetchRate = () -> {
    Thread.sleep(300);
    return 1.70;
};

Future<Double> future = pool.submit(fetchRate);
// ... do other work ...
Double rate = future.get(1, TimeUnit.SECONDS);    // blocks; timeout!
```

`Future` methods: `get()`, `get(timeout)`, `isDone()`, `cancel(true)`.

Exceptions inside the task come back wrapped in `ExecutionException`:
```java
try {
    future.get();
} catch (ExecutionException e) {
    Throwable real = e.getCause();
}
```

## 4. invokeAll / invokeAny

```java
List<Callable<String>> tasks = List.of(() -> call("A"), () -> call("B"), () -> call("C"));
List<Future<String>> results = pool.invokeAll(tasks);        // wait for all
String fastest = pool.invokeAny(tasks);                      // first successful
```

## 5. Scheduled tasks

```java
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);
scheduler.scheduleAtFixedRate(() -> refreshRates(), 0, 5, TimeUnit.MINUTES);
scheduler.schedule(() -> sendReminder(), 10, TimeUnit.SECONDS);
```
(In Spring we use `@Scheduled`.)

## 6. Sizing thread pools

- **CPU-bound** tasks (calculations): `≈ number of cores`.
- **I/O-bound** tasks (HTTP, DB): more threads, `cores × (1 + wait time / compute time)`, or simply **virtual threads**.

### Custom ThreadPoolExecutor (production style)
```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
        4, 8,                                   // core, max threads
        60, TimeUnit.SECONDS,                   // idle keep-alive
        new ArrayBlockingQueue<>(100),          // BOUNDED queue
        Thread.ofPlatform().name("report-", 0).factory(),
        new ThreadPoolExecutor.CallerRunsPolicy());   // back-pressure when full
```
Unbounded queues hide overload until you run out of memory.

## 7. Step by step: parallel statement generation

```java
record Statement(String iban, String pdfPath) { }

List<String> ibans = loadIbans();                 // 500 accounts
try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
    List<Future<Statement>> futures = ibans.stream()
            .map(iban -> pool.submit(() -> generateStatement(iban)))
            .toList();

    int ok = 0, failed = 0;
    for (Future<Statement> f : futures) {
        try {
            f.get(30, TimeUnit.SECONDS);
            ok++;
        } catch (ExecutionException | TimeoutException e) {
            failed++;
        }
    }
    System.out.printf("Done: %d ok, %d failed%n", ok, failed);
}
```
