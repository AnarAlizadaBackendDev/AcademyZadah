> **Goal:** get hired: CV, GitHub, LinkedIn, interview preparation and mock interviews.

## 1. CV for a Java backend developer

One page (two at most), clean, in English.

```
NAME SURNAME
Java Backend Developer | Spring Boot, PostgreSQL, Kafka
email | phone | GitHub | LinkedIn | city

SUMMARY (2–3 lines)
Backend developer with hands-on experience building secure, tested Spring Boot microservices ...

PROJECTS (for juniors this is the main section)
Payment-Link Platform | Java 21, Spring Boot, PostgreSQL, Kafka, Redis, Docker, Railway  [live] [GitHub]
• Designed 3 services with transactional outbox and idempotent consumers to deliver payment events reliably
• Implemented JWT security with role-based and ownership checks; 85% branch coverage with Testcontainers
• Deployed with GitHub Actions CI/CD; p95 latency 120 ms under 200 req/s load test

EXPERIENCE (internships, freelance, previous non-IT jobs briefly)
SKILLS: Java 21, Spring Boot/Security/Data JPA, PostgreSQL, Kafka, Redis, Docker, Kubernetes basics, JUnit/Mockito/Testcontainers, Git, CI/CD
EDUCATION / CERTIFICATES
```
Rules:
- Bullet = **action + technology + result** (numbers when possible).
- Tailor keywords to each job post.
- No photos/birth dates needed for international applications; no long lists of school courses.

## 2. GitHub & LinkedIn

- Pin 3–4 best repos: final project, month 8 microservices, one algorithmic/library project.
- Each README: what, why, architecture image, how to run, live link.
- Consistent commit history (not one giant commit).
- LinkedIn headline: "Java Backend Developer | Spring Boot | Microservices"; about section; project posts; connect with recruiters and developers in Baku and remote companies.

## 3. Interview process

1. HR screening (motivation, salary expectations, English).
2. Technical interview (Java, Spring, SQL, system design light).
3. Live coding or take-home task.
4. Team/manager interview.

## 4. Question bank (practice!)

**Java core**: equals/hashCode contract · String immutability · HashMap internals · checked vs unchecked · streams vs loops · Optional · records · virtual threads · volatile/synchronized · ExecutorService · GC basics.

**Spring**: IoC/DI · bean scopes · @Transactional internals & self-invocation · @RestControllerAdvice · profiles · Spring Boot auto-configuration · Spring Security filter chain · JWT flow.

**JPA & SQL**: N+1 · lazy vs eager · entity states · optimistic vs pessimistic locking · indexes & EXPLAIN · isolation levels · joins · window functions · second highest salary.

**Microservices**: sync vs async · Kafka partitions & consumer groups · outbox · saga · circuit breaker · idempotency · observability.

**Behavioural (STAR: Situation, Task, Action, Result)**: hardest bug · disagreement in a code review · a time you missed a deadline · what you learned from a failure.

## 5. Live coding tips

- Clarify the problem and examples first.
- Think aloud; start with a simple correct solution, then optimize.
- Write tests/examples; handle edge cases (null, empty, large input).
- Typical tasks: string manipulation, maps/counting, two pointers, simple LRU cache, REST endpoint with validation, SQL query.

```java
// LRU cache in 10 lines: a classic
class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;
    LruCache(int capacity) { super(16, 0.75f, true); this.capacity = capacity; }
    @Override protected boolean removeEldestEntry(Map.Entry<K, V> eldest) { return size() > capacity; }
}
```

## 6. Salary & offers

- Research market ranges (local job boards, LinkedIn, community chats).
- Consider total package: salary, learning, mentorship, product quality, remote options.
- First job: prioritize a strong team and mentorship over a small salary difference.

## 7. Mock interviews

Each student gets one 60-minute mock interview with the mentor:
- 10 min intro & project story
- 25 min technical questions
- 20 min live coding
- 5 min feedback with a written improvement plan
