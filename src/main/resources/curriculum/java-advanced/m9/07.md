> **Goal:** deploy the final project to production and present it like a professional.
> **Duration:** 120 min + demo day

## 1. Go-live checklist

**Build & deploy**
- [ ] CI green: format, tests, coverage, scans
- [ ] Images tagged by commit SHA
- [ ] Automatic deploy to staging; production deploy with approval
- [ ] Migrations backward compatible; rollback plan

**Runtime**
- [ ] prod profile, secrets from secret manager / platform variables
- [ ] HTTPS, custom domain (optional), CORS restricted
- [ ] health checks configured on the platform
- [ ] resource limits, graceful shutdown

**Data**
- [ ] managed DB, backups enabled, restore tested once
- [ ] seed/demo data for the presentation (separate from real data)

**Observability**
- [ ] structured logs, trace ids
- [ ] dashboard (RED + business metrics)
- [ ] uptime monitor/alert (e.g. UptimeRobot, Cloud Monitoring)

**Docs**
- [ ] README: overview, architecture diagram, how to run locally, live URL, API docs link, test strategy, demo credentials
- [ ] ADRs (Architecture Decision Records) for 3–5 key decisions

```markdown
# ADR-003: Use the transactional outbox for payment events
Status: accepted
Context: payment status must reach merchant dashboards reliably...
Decision: outbox table + relay with SKIP LOCKED...
Consequences: at-least-once delivery → idempotent consumers required...
```

## 2. Demo day presentation (15 minutes)

| Minutes | Content |
|---|---|
| 2 | Problem and users |
| 4 | **Live demo** of the main user journey (have a backup video!) |
| 4 | Architecture diagram + one deep dive (the hardest problem you solved) |
| 2 | Quality: tests, CI/CD, observability dashboard |
| 2 | What you learned, what you'd do next |
| 1 | Q&A starter |

Tips:
- Rehearse twice with a timer.
- Use realistic demo data.
- Show the code only for the interesting part.
- Expect questions: "Why Kafka here?", "How do you prevent double payments?", "What happens if service X is down?"

## 3. Evaluation (final project, out of 100)

| Criteria | Points |
|---|---|
| Functionality & domain quality | 20 |
| Architecture & design decisions | 15 |
| Security | 10 |
| Async/resilience | 10 |
| Tests | 15 |
| CI/CD & deployment | 10 |
| Observability | 5 |

≥ 75 → **Java Advanced certificate**; ≥ 90 → certificate "with distinction" + recommendation letter.

## 4. After the demo

- Pin the project on GitHub; add the live URL and screenshots.
- Write a LinkedIn post about what you built (architecture image + key learnings).
- Collect feedback from the mentor and classmates; make a final improvement PR.
