> **Goal:** implement the final project's core with professional engineering practices.
> **Duration:** 120 min (workshop) + 2 weeks

## 1. Working like a team

- One issue → one branch → one PR (small!).
- PR template:
```markdown
## What
## Why (issue #)
## How to test
## Checklist
- [ ] tests added
- [ ] docs/OpenAPI updated
- [ ] migrations backward compatible
```
- Peer reviews between students (each PR reviewed by one classmate + mentor spot checks).
- Main always deployable.

## 2. Implementation order (vertical slices)

Build **end-to-end slices**, not layers:
1. Slice 1: "merchant registers and logs in": migration → entity → service → API → security → tests → deploy.
2. Slice 2: "merchant creates a payment link".
3. Slice 3: "customer pays a link" (mock processor) ...
Each slice is demoable.

## 3. Domain modeling checkpoints

- Are invariants inside entities/value objects (`Money`, `PaymentLink.markPaid()`)?
- Are state transitions explicit and tested?
- Are money amounts `BigDecimal` with currency?
- Are ids for public use unguessable?

## 4. Ledger example (for wallet/payments projects)

Double-entry bookkeeping: every transfer creates two entries that sum to zero.
```sql
CREATE TABLE ledger_entries (
    id             BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    transaction_id UUID NOT NULL,
    account_id     BIGINT NOT NULL REFERENCES accounts (id),
    amount         NUMERIC(19,4) NOT NULL,       -- negative = debit, positive = credit
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- invariant: SUM(amount) per transaction_id = 0
-- balance = SUM(amount) per account (or a maintained balance column updated in the same transaction)
```
Never update or delete ledger entries: corrections are new entries.

## 5. Mentor checkpoints (each week)

| Check | Questions |
|---|---|
| Design | does the code match the spec? any shortcuts in the domain? |
| Tests | are critical paths and failure paths tested? |
| Security | ownership checks? secrets? |
| Ops | does it run with one command? CI green? |
| Scope | on track for the deadline? what to cut? |

## 6. Common problems & fixes

| Problem | Fix |
|---|---|
| giant service class | split by use case; move logic to domain |
| N+1 in list endpoints | projections / fetch joins |
| flaky async tests | Awaitility, idempotent consumers |
| "it works locally only" | Compose + CI parity, env vars |
| scope creep | must/should/could; finish musts first |

## 7. Workshop activities

1. Live code review of 2 student PRs on the projector.
2. Pair-debugging session on the hardest bug of the week.
3. Update the sprint board; re-plan.
