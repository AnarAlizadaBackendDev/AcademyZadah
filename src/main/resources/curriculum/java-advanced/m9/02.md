> **Goal:** deploy and operate services on Kubernetes.
> **Duration:** 120 min

## 1. Why Kubernetes?

Running 20 containers on many servers needs: scheduling, restarts on failure, scaling, rolling updates, service discovery, config and secrets. **Kubernetes (K8s)** does this declaratively: you describe the desired state; K8s makes it real.

## 2. Core objects

| Object | Purpose |
|---|---|
| **Pod** | one or more containers running together (smallest unit) |
| **Deployment** | desired number of pod replicas, rolling updates |
| **Service** | stable name & load balancing to pods (`orders-service:8080`) |
| **Ingress** | HTTP routing from outside to services |
| **ConfigMap** | non-secret configuration |
| **Secret** | sensitive config (base64, use external secret managers) |
| **Namespace** | isolation (dev/staging/prod or per team) |
| HPA | horizontal pod autoscaling |

## 4. Manifests for a Spring Boot service

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: orders
spec:
  replicas: 2
  selector:
    matchLabels: { app: orders }
  template:
    metadata:
      labels: { app: orders }
    spec:
      containers:
        - name: orders
          image: ghcr.io/me/shop-orders:3f2a1c9
          ports: [{ containerPort: 8080 }]
          envFrom:
            - configMapRef: { name: orders-config }
            - secretRef: { name: orders-secrets }
          resources:
            requests: { cpu: 250m, memory: 512Mi }
            limits:   { memory: 768Mi }
          readinessProbe:
            httpGet: { path: /actuator/health/readiness, port: 8080 }
            periodSeconds: 5
          livenessProbe:
            httpGet: { path: /actuator/health/liveness, port: 8080 }
            initialDelaySeconds: 30
---
apiVersion: v1
kind: Service
metadata:
  name: orders
spec:
  selector: { app: orders }
  ports: [{ port: 8080, targetPort: 8080 }]
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: orders-config
data:
  SPRING_PROFILES_ACTIVE: prod
  SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/orders
```
```bash
kubectl create secret generic orders-secrets --from-literal=SPRING_DATASOURCE_PASSWORD=...
kubectl apply -f k8s/
kubectl get pods,svc
kubectl logs -f deploy/orders
kubectl describe pod <name>
kubectl rollout status deploy/orders
kubectl rollout undo deploy/orders            # rollback
kubectl scale deploy/orders --replicas=4
kubectl port-forward svc/orders 8081:8080
```

## 5. Probes

- **Readiness**: "can I receive traffic?" (DB reachable, warmed up). Failing → removed from Service, not restarted.
- **Liveness**: "am I stuck?" Failing → container restarted. Keep it simple (don't check the DB here!).
- **Startup** probe for slow-starting apps.

Spring Boot exposes both automatically in Kubernetes.

## 6. Rolling updates & graceful shutdown

Deployment replaces pods gradually (`maxUnavailable`, `maxSurge`). With `server.shutdown=graceful` and a preStop delay, in-flight requests finish before the pod dies.

## 7. Autoscaling

```bash
kubectl autoscale deployment orders --cpu-percent=70 --min=2 --max=10
```
