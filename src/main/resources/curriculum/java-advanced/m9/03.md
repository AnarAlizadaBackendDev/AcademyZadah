> **Goal:** deploy Spring Boot applications to the cloud (GCP and Railway) with managed databases.
> **Duration:** 120 min

## 1. Hosting options

| Option | Effort | Good for |
|---|---|---|
| **PaaS** (Railway, Render, Heroku, Fly.io) | lowest | startups, MVPs, portfolios, **this academy website** |
| **Serverless containers** (GCP Cloud Run, AWS App Runner) | low | APIs with variable traffic, scale to zero |
| **Managed Kubernetes** (GKE, EKS, AKS) | high | many services, platform teams |
| VMs (Compute Engine, EC2) | medium/high | legacy, special needs |

Managed databases (Cloud SQL, RDS, Railway Postgres) handle backups, patches and failover: use them instead of DB containers in production.

## 2. Deploying to Railway (step by step)

1. Push your project (with a `Dockerfile`) to GitHub.
2. railway.app → New Project → Deploy from GitHub repo.
3. Add **PostgreSQL** to the project.
4. Service variables:
```
SPRING_PROFILES_ACTIVE=prod
SPRING_DATASOURCE_URL=jdbc:postgresql://${{Postgres.PGHOST}}:${{Postgres.PGPORT}}/${{Postgres.PGDATABASE}}
SPRING_DATASOURCE_USERNAME=${{Postgres.PGUSER}}
SPRING_DATASOURCE_PASSWORD=${{Postgres.PGPASSWORD}}
```
5. `server.port=${PORT:8080}` in your config (Railway provides `PORT`).
6. Networking → generate a domain or attach a custom domain (HTTPS automatic).
7. Add a **volume** if the app stores uploaded files.
Every push to main redeploys automatically.

## 3. Deploying to GCP Cloud Run

```bash
gcloud auth login
gcloud config set project shop-prod
gcloud services enable run.googleapis.com sqladmin.googleapis.com artifactregistry.googleapis.com

# managed PostgreSQL
gcloud sql instances create shop-db --database-version=POSTGRES_16 --tier=db-f1-micro --region=europe-west3
gcloud sql databases create shop --instance=shop-db

# image
gcloud artifacts repositories create shop --repository-format=docker --location=europe-west3
docker build -t europe-west3-docker.pkg.dev/shop-prod/shop/api:v1 .
docker push europe-west3-docker.pkg.dev/shop-prod/shop/api:v1

# deploy
gcloud run deploy shop-api \
  --image europe-west3-docker.pkg.dev/shop-prod/shop/api:v1 \
  --region europe-west3 \
  --add-cloudsql-instances shop-prod:europe-west3:shop-db \
  --set-env-vars SPRING_PROFILES_ACTIVE=prod \
  --set-secrets SPRING_DATASOURCE_PASSWORD=db-password:latest \
  --min-instances 1 --memory 1Gi
```
Secrets from **Secret Manager**; DB connection via the Cloud SQL connector.

## 4. Production configuration checklist

- [ ] `prod` profile; no dev tools; Swagger disabled or protected
- [ ] secrets from environment/secret manager
- [ ] Flyway migrations on startup; `ddl-auto=validate`
- [ ] JSON logs to stdout; log level INFO
- [ ] health endpoint for the platform
- [ ] HTTPS, custom domain, HSTS
- [ ] DB backups enabled and **restore tested**
- [ ] resource limits/memory settings
- [ ] alerts on errors and downtime (uptime monitor)

## 5. Cost awareness

- Scale-to-zero vs `min-instances=1` (cold starts for Java ~ seconds; consider CDS/CRaC or GraalVM native image for faster starts).
- Right-size DB tiers; delete unused resources; set budget alerts.
