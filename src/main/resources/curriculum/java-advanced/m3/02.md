> **Goal:** understand ORM, JPA and Hibernate, and the persistence context.
> **Duration:** 120 min

## 1. The object-relational mismatch

| Java | SQL |
|---|---|
| objects, references | rows, foreign keys |
| inheritance | no inheritance |
| collections | join tables |
| identity (`==`) | primary key |

Mapping by hand (JDBC) = lots of repetitive code. An **ORM** (Object-Relational Mapper) does it for us.

- **JPA** (Jakarta Persistence API): the **specification** (interfaces, annotations).
- **Hibernate**: the most popular **implementation**.
- **Spring Data JPA**: a layer on top that generates repositories (month 4).

## 2. First entity

```java
import jakarta.persistence.*;

@Entity
@Table(name = "customers")
public class Customer {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "full_name", nullable = false, length = 120)
    private String fullName;

    @Column(nullable = false, unique = true)
    private String email;

    protected Customer() { }           // JPA needs a no-arg constructor

    public Customer(String fullName, String email) {
        this.fullName = fullName;
        this.email = email;
    }
    // getters, business methods
}
```

## 3. EntityManager

```java
EntityManagerFactory emf = Persistence.createEntityManagerFactory("shop");
EntityManager em = emf.createEntityManager();

em.getTransaction().begin();
Customer c = new Customer("Leyla", "leyla@mail.az");
em.persist(c);                         // INSERT (at flush/commit)
em.getTransaction().commit();

Customer found = em.find(Customer.class, c.getId());   // SELECT
em.close();
```
(In Spring, you don't create these manually: Spring Boot configures everything.)

## 4. Persistence context and entity states

The **persistence context** is a first-level cache of managed entities inside a transaction.

```
          persist()
NEW ─────────────────▶ MANAGED ──── commit/flush → SQL
(transient)              │  ▲
                 detach()│  │merge()
                close()  ▼  │
                       DETACHED
          remove()
MANAGED ─────────────▶ REMOVED ── commit → DELETE
```

### Dirty checking: no `update()` call needed!
```java
em.getTransaction().begin();
Customer c = em.find(Customer.class, 1L);   // managed
c.setEmail("new@mail.az");                  // just change the object
em.getTransaction().commit();               // Hibernate detects the change → UPDATE
```

### First-level cache
```java
Customer a = em.find(Customer.class, 1L);   // SQL
Customer b = em.find(Customer.class, 1L);   // no SQL, same object
a == b;                                     // true
```

### Flush
Changes are written to the DB at **flush** (before commit, before some queries, or `em.flush()`). SQL doesn't run at the moment you call `persist`.

## 5. Configuration (plain Hibernate) / Spring Boot

Spring Boot `application.yml`:
```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/shop
    username: shop
    password: secret
  jpa:
    hibernate:
      ddl-auto: validate      # never 'update'/'create' in production; use migrations
    properties:
      hibernate.format_sql: true
    show-sql: true            # learning only
```
