> **Goal:** detect and fix the N+1 problem and choose fetching strategies.
> **Duration:** 120 min

## 1. Lazy vs eager

| | Lazy | Eager |
|---|---|---|
| Loads related data | when accessed | immediately |
| Default for | `@OneToMany`, `@ManyToMany` | `@ManyToOne`, `@OneToOne` |
| Recommendation | **always lazy** | avoid |

Eager loading everywhere = huge queries; and it doesn't even prevent N+1 for queries.

## 2. The N+1 problem

```java
List<Order> orders = orderRepository.findAll();      // 1 query
for (Order o : orders) {
    System.out.println(o.getCustomer().getFullName()); // +1 query PER order
}
```
100 orders → **101 queries**. In production with 10,000 rows it kills performance, and it's invisible without SQL logs.

## 3. Detecting it

```yaml
spring.jpa.show-sql: true
logging.level.org.hibernate.SQL: debug
logging.level.org.hibernate.orm.jdbc.bind: trace     # parameters
spring.jpa.properties.hibernate.generate_statistics: true
```
Tools: Hibernate statistics, `datasource-proxy` / `p6spy` query counters, assert query counts in tests.

## 4. Fix 1: JOIN FETCH

```java
@Query("SELECT o FROM Order o JOIN FETCH o.customer WHERE o.status = :status")
List<Order> findWithCustomer(OrderStatus status);

@Query("SELECT DISTINCT o FROM Order o JOIN FETCH o.items i JOIN FETCH i.product WHERE o.id = :id")
Optional<Order> findDetailed(Long id);
```
⚠️ JOIN FETCH of a collection + pagination → Hibernate paginates **in memory** (warning `HHH90003004`). Don't fetch two collections at once (`MultipleBagFetchException`).

## 5. Fix 2: Entity graphs

```java
@EntityGraph(attributePaths = {"customer", "items", "items.product"})
Optional<Order> findById(Long id);
```

## 6. Fix 3: Batch fetching

```yaml
spring.jpa.properties.hibernate.default_batch_fetch_size: 50
```
Hibernate loads lazy associations for 50 parents in **one** `IN (...)` query: N+1 becomes 1 + N/50. Great global default.

## 7. Fix 4: DTO projections (best for read screens)

```java
public record OrderSummary(Long id, String customerName, BigDecimal total, OrderStatus status) { }

@Query("""
       SELECT new az.academy.shop.OrderSummary(o.id, c.fullName, o.total, o.status)
       FROM Order o JOIN o.customer c
       WHERE o.createdAt > :since
       """)
List<OrderSummary> summaries(Instant since);
```
Only the needed columns, no entities, no dirty checking, no lazy surprises.

## 8. Pagination with collections: two-step

```java
Page<Long> ids = orderRepository.findIds(pageable);                 // 1. page of ids
List<Order> orders = orderRepository.findWithItemsByIdIn(ids.getContent());   // 2. fetch with JOIN FETCH
```

## 9. Open Session in View

Spring Boot enables `spring.jpa.open-in-view=true` by default: lazy loading works in controllers/views, hiding N+1 problems and holding DB connections longer. Many teams set it to `false` in APIs and fetch explicitly.

## 10. Hands-on

2. Fix with JOIN FETCH; count again.
3. Fix with batch size; compare.
4. Fix with a DTO projection; compare.
5. Write a test that asserts the number of SQL statements.
