## 3. Querying with PreparedStatement

```java
public Optional<Customer> findById(long id) {
    String sql = "SELECT id, full_name, email FROM customers WHERE id = ?";
    try (Connection conn = dataSource.getConnection();
         PreparedStatement ps = conn.prepareStatement(sql)) {
        ps.setLong(1, id);
        try (ResultSet rs = ps.executeQuery()) {
            if (rs.next()) {
                return Optional.of(new Customer(rs.getLong("id"), rs.getString("full_name"), rs.getString("email")));
            }
            return Optional.empty();
        }
    } catch (SQLException e) {
        throw new DataAccessException("Cannot load customer " + id, e);
    }
}
```

## 4. SQL injection: never concatenate input

```java
// ❌ DANGEROUS
String sql = "SELECT * FROM users WHERE email = '" + email + "'";
// email = "' OR '1'='1"  → returns ALL users
// email = "'; DROP TABLE users; --" → disaster

// ✅ parameters are sent separately and never interpreted as SQL
PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE email = ?");
ps.setString(1, email);
```

## 5. Insert, update and generated keys

```java
public long insert(Customer c) {
    String sql = "INSERT INTO customers (full_name, email) VALUES (?, ?)";
    try (Connection conn = dataSource.getConnection();
         PreparedStatement ps = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
        ps.setString(1, c.fullName());
        ps.setString(2, c.email());
        ps.executeUpdate();
        try (ResultSet keys = ps.getGeneratedKeys()) {
            keys.next();
            return keys.getLong(1);
        }
    } catch (SQLException e) {
        throw new DataAccessException("Insert failed", e);
    }
}
```

Batch:
```java
for (Product p : products) {
    ps.setString(1, p.name());
    ps.setBigDecimal(2, p.price());
    ps.addBatch();
}
ps.executeBatch();
```

## 6. Transactions in JDBC

```java
try (Connection conn = dataSource.getConnection()) {
    conn.setAutoCommit(false);
    try {
        debit(conn, fromId, amount);
        credit(conn, toId, amount);
        conn.commit();
    } catch (Exception e) {
        conn.rollback();
        throw e;
    }
}
```
Both operations must use the **same connection**.

## 7. Connection pooling with HikariCP

Opening a DB connection takes milliseconds (TCP + auth). A pool keeps connections open and reuses them.

```java
HikariConfig cfg = new HikariConfig();
cfg.setJdbcUrl("jdbc:postgresql://localhost:5432/shop");
cfg.setUsername("shop");
cfg.setPassword("secret");
cfg.setMaximumPoolSize(10);
cfg.setConnectionTimeout(3000);
DataSource dataSource = new HikariDataSource(cfg);
```
`conn.close()` returns the connection to the pool. Spring Boot uses Hikari by default.

Pool size rule of thumb: small! `connections ≈ (cores × 2) + effective_spindle_count`; 10–20 is enough for most services.
