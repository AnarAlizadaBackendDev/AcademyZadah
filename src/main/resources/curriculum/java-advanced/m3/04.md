> **Goal:** map relationships between entities correctly.
> **Duration:** 120 min

## 1. @ManyToOne: the most common

```java
@Entity
public class Order {
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "customer_id")
    private Customer customer;
}
```
Always set `fetch = LAZY` (default for ManyToOne is EAGER!).

## 2. @OneToMany: the inverse side

```java
@Entity
public class Order {
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(Product product, int qty) {         // helper keeps both sides in sync
        OrderItem item = new OrderItem(this, product, qty, product.getPrice());
        items.add(item);
    }

    public void removeItem(OrderItem item) {
        items.remove(item);                                   // orphanRemoval deletes the row
    }
}

@Entity
public class OrderItem {
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "order_id")
    private Order order;                                      // OWNING side (has the FK)
}
```

### Owning side
- The side with the **foreign key** (`@JoinColumn`) owns the relationship; Hibernate writes the FK from it.
- `mappedBy` marks the inverse side.
- Changing only the inverse side does **not** update the database.

## 3. Cascade

| Cascade | Effect |
|---|---|
| `PERSIST` | saving parent saves children |
| `MERGE` | merging parent merges children |
| `REMOVE` | deleting parent deletes children |
| `ALL` | all of the above |

Use cascade only **from parent to children that belong to it** (Order → OrderItem). Never cascade from `OrderItem` to `Product`!

`orphanRemoval = true`: removing a child from the collection deletes it.

## 4. @ManyToMany

```java
@Entity
public class Student {
    @ManyToMany
    @JoinTable(name = "enrollments",
               joinColumns = @JoinColumn(name = "student_id"),
               inverseJoinColumns = @JoinColumn(name = "course_id"))
    private Set<Course> courses = new HashSet<>();
}

@Entity
public class Course {
    @ManyToMany(mappedBy = "courses")
    private Set<Student> students = new HashSet<>();
}
```
⚠️ If the join table needs extra columns (enrolled_at, grade), model it as its **own entity** `Enrollment` with two `@ManyToOne`. In practice this is almost always the case.

## 5. @OneToOne

```java
@Entity
public class Customer {
    @OneToOne(mappedBy = "customer", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private CustomerProfile profile;
}
@Entity
public class CustomerProfile {
    @Id private Long id;
    @MapsId @OneToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "customer_id")
    private Customer customer;          // shares the primary key
}
```

## 6. Bidirectional or unidirectional?

Prefer **unidirectional `@ManyToOne`** and add the `@OneToMany` side only when you really navigate it (and it's small). Large collections (a customer with 100k transactions) should be loaded with **queries**, not with a collection.

## 7. LazyInitializationException

```java
Order order = orderRepository.findById(1L).orElseThrow();   // transaction ends here
order.getItems().size();   // 💥 LazyInitializationException: no session
```
Fixes: load what you need in the query (`JOIN FETCH`, next lesson), work inside a transaction (`@Transactional` service method), or map to DTOs.
