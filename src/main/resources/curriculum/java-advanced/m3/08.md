> **Goal:** version the database schema with Flyway and Liquibase; complete the persistence project.
> **Duration:** 120 min + project week

## 1. Why migrations?

- `ddl-auto: update` is unpredictable, can't rename or migrate data, and is dangerous in production.
- Every environment (dev, test, prod) must have the **same schema**, reproducibly.
- Schema changes are reviewed in pull requests like code.

## 2. Flyway

```groovy
implementation 'org.flywaydb:flyway-core'
implementation 'org.flywaydb:flyway-database-postgresql'
```
```
src/main/resources/db/migration/
├── V1__create_customers.sql
├── V2__create_products.sql
├── V3__add_phone_to_customers.sql
└── R__refresh_views.sql          (repeatable)
```
Rules:
- File name: `V<version>__<description>.sql` (two underscores).
- Applied **once**, in order; recorded in `flyway_schema_history`.
- **Never edit** an applied migration (checksum mismatch!). Create a new one.

```sql
-- V3__add_phone_to_customers.sql
ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
CREATE INDEX idx_customers_phone ON customers (phone);
```
Spring Boot runs Flyway automatically at startup. Set `spring.jpa.hibernate.ddl-auto=validate` so Hibernate checks entities against the migrated schema.

## 3. Liquibase

```yaml
# db/changelog/db.changelog-master.yaml
databaseChangeLog:
  - changeSet:
      id: 1
      author: anar
      changes:
        - createTable:
            tableName: customers
            columns:
              - column: { name: id, type: BIGINT, autoIncrement: true, constraints: { primaryKey: true } }
              - column: { name: email, type: VARCHAR(160), constraints: { nullable: false, unique: true } }
  - changeSet:
      id: 2
      author: anar
      changes:
        - addColumn:
            tableName: customers
            columns:
              - column: { name: phone, type: VARCHAR(20) }
      rollback:
        - dropColumn: { tableName: customers, columnName: phone }
```
| | Flyway | Liquibase |
|---|---|---|
| Format | plain SQL (also Java) | XML/YAML/JSON/SQL |
| Rollback | manual (new migration) | built-in rollback blocks |
| Learning curve | very low | medium |
| DB-agnostic | no (SQL) | yes (changesets) |

Many banks use Liquibase; startups often Flyway. Learn both concepts.

## 4. Zero-downtime changes (expand & contract)

Renaming a column used by a running app breaks it. Do it in steps:
1. **Expand**: add new column, write to both.
2. Backfill data.
3. Switch reads to the new column (deploy).
4. **Contract**: drop the old column (later deploy).

Large tables: create indexes `CONCURRENTLY`, backfill in batches.

## 5. 🏁 Month 3 Project: Shop Persistence Layer

### Requirements
Spring Boot + JPA application over your shop schema:
1. Flyway migrations for the whole schema (from your month 2 SQL) + seed data migration for categories.
2. Entities with correct mappings: embeddables, enums, relationships, auditing, `@Version` on products/inventory.
3. Repositories/services:
   - `CatalogService`: dynamic product search (Criteria) with paging and sorting
   - `CheckoutService`: transactional order creation, stock reservation with locking, idempotency key
   - `ReportService`: DTO projections for top products, revenue per month
4. No N+1 problems: prove with query-count tests.
5. Integration tests against PostgreSQL (Testcontainers preview, or Docker DB).
6. README: model diagram, design decisions, concurrency strategy.

### Evaluation
| Criteria | Points |
|---|---|
| Mapping correctness | 20 |
| Migrations quality | 15 |
| Transactions & concurrency | 25 |
| Query performance (N+1, projections) | 20 |
| Tests & docs | 20 |
