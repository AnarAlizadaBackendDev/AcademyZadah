## 1. JPQL: queries on entities, not tables

```java
List<Product> cheap = em.createQuery(
        "SELECT p FROM Product p WHERE p.price < :max ORDER BY p.price", Product.class)
    .setParameter("max", new BigDecimal("50"))
    .setMaxResults(20)
    .getResultList();
```
- Uses **entity and field names** (`Product`, `p.price`), not table/column names.
- Named parameters `:max` (never concatenate!).

### Joins and aggregates
```sql
SELECT c.fullName, COUNT(o), SUM(o.total)
FROM Order o JOIN o.customer c
WHERE o.status = :status
GROUP BY c.fullName
HAVING SUM(o.total) > 1000
```

### Updates/deletes in bulk
```java
@Modifying
@Query("UPDATE Order o SET o.status = 'CANCELLED' WHERE o.status = 'NEW' AND o.createdAt < :before")
int cancelOld(Instant before);
```
⚠️ Bulk operations bypass the persistence context (managed entities become stale).

## 3. Criteria API: dynamic queries

When filters are optional (search screens), concatenating JPQL strings is ugly and error-prone.

```java
public List<Product> search(ProductFilter f) {
    CriteriaBuilder cb = em.getCriteriaBuilder();
    CriteriaQuery<Product> q = cb.createQuery(Product.class);
    Root<Product> p = q.from(Product.class);

    List<Predicate> predicates = new ArrayList<>();
    if (f.name() != null) predicates.add(cb.like(cb.lower(p.get("name")), "%" + f.name().toLowerCase() + "%"));
    if (f.minPrice() != null) predicates.add(cb.ge(p.get("price"), f.minPrice()));
    if (f.maxPrice() != null) predicates.add(cb.le(p.get("price"), f.maxPrice()));
    if (f.categoryId() != null) predicates.add(cb.equal(p.get("category").get("id"), f.categoryId()));

    q.where(predicates.toArray(Predicate[]::new)).orderBy(cb.asc(p.get("price")));
    return em.createQuery(q).setMaxResults(50).getResultList();
}
```
Spring Data's `Specification` (month 4) wraps this nicely. Alternatives: Querydsl, jOOQ.

## 4. Native SQL

For database-specific features (window functions, JSONB, CTEs, full-text search):
```java
@Query(value = """
        SELECT p.* FROM products p
        WHERE to_tsvector('simple', p.name || ' ' || p.description) @@ plainto_tsquery(:text)
        LIMIT 20
        """, nativeQuery = true)
List<Product> fullTextSearch(String text);

@Query(value = """
        SELECT category_id AS categoryId, name, price,
               rank() OVER (PARTITION BY category_id ORDER BY price DESC) AS rnk
        FROM products
        """, nativeQuery = true)
List<RankedProduct> ranked();      // interface projection
```

## 5. Choosing

| Need | Use |
|---|---|
| simple lookups | Spring Data derived methods (`findByEmail`) |
| fixed queries | JPQL `@Query` |
| optional filters | Criteria / Specification |
| DB-specific / reporting | native SQL |
| read-only lists | DTO projections |
