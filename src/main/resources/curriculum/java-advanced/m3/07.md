## 1. Transaction boundaries

A transaction should cover one **business operation** (place order, transfer money): typically one service method.

```java
@Service
public class TransferService {
    @Transactional
    public void transfer(Long fromId, Long toId, BigDecimal amount) {
        Account from = accounts.findById(fromId).orElseThrow();
        Account to = accounts.findById(toId).orElseThrow();
        from.withdraw(amount);
        to.deposit(amount);
        transfers.save(new Transfer(from, to, amount));
    }   // commit here; any RuntimeException → rollback
}
```
(How `@Transactional` works internally: month 4.)

Keep transactions **short**: no HTTP calls or file uploads inside them.

## 2. Optimistic locking with @Version

```java
@Entity
public class Account {
    @Id private Long id;
    private BigDecimal balance;

    @Version
    private long version;
}
```
Hibernate generates:
```sql
UPDATE account SET balance = ?, version = 8 WHERE id = ? AND version = 7
```
If another transaction changed the row first → 0 rows → `OptimisticLockException` (`ObjectOptimisticLockingFailureException` in Spring). Handle by **retrying** or telling the user "data changed, reload".

Best for: low contention, user edits (forms), most business entities.

## 3. Pessimistic locking

```java
@Lock(LockModeType.PESSIMISTIC_WRITE)                    // SELECT ... FOR UPDATE
@Query("SELECT a FROM Account a WHERE a.id = :id")
Optional<Account> findForUpdate(Long id);

@QueryHints(@QueryHint(name = "jakarta.persistence.lock.timeout", value = "3000"))
```
Best for: high contention on the same rows (hot accounts, stock of a popular product). Remember lock **ordering** to avoid deadlocks.

## 4. Retry for optimistic failures

```java
@Retryable(retryFor = ObjectOptimisticLockingFailureException.class, maxAttempts = 3,
           backoff = @Backoff(delay = 50, multiplier = 2))
@Transactional
public void reserveStock(Long productId, int qty) { ... }
```
(Spring Retry; or a simple loop.)

## 5. Idempotency (payments!)

Networks fail; clients retry. The same payment must not be charged twice.
```java
@Entity
@Table(uniqueConstraints = @UniqueConstraint(columnNames = "idempotency_key"))
public class Payment { ... private String idempotencyKey; }
```
Client sends `Idempotency-Key` header; if a payment with that key exists, return it instead of creating a new one.

## 6. Auditing

Spring Data JPA auditing:
```java
@EnableJpaAuditing
@Configuration class JpaConfig { }

@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class Auditable {
    @CreatedDate private Instant createdAt;
    @LastModifiedDate private Instant updatedAt;
    @CreatedBy private String createdBy;          // needs an AuditorAware bean
    @LastModifiedBy private String updatedBy;
}
```
For full history (who changed what, old/new values) use **Hibernate Envers** (`@Audited`) or an append-only events table. Banks must keep an audit trail.
