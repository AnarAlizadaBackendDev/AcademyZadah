## 1. Logging in Spring Boot

SLF4J API + Logback implementation (default).

```java
private static final Logger log = LoggerFactory.getLogger(OrderService.class);

log.info("Order {} placed by customer {}", order.getId(), customerId);   // placeholders, not +
log.warn("Payment retry {} for order {}", attempt, orderId);
log.error("Payment failed for order {}", orderId, exception);             // exception last → stack trace
log.debug("Cart content: {}", cart);
```

| Level | Use for |
|---|---|
| ERROR | failures needing attention |
| WARN | unexpected but handled |
| INFO | business events (order placed, user registered) |
| DEBUG | developer details |
| TRACE | very detailed |

```yaml
logging:
  level:
    root: info
    az.academy.shop: debug
    org.hibernate.SQL: debug
  file:
    name: logs/shop.log
```

## 2. What (not) to log

- ✅ ids, statuses, durations, decisions.
- ❌ passwords, full card numbers, CVV, tokens, personal data (GDPR/PCI DSS).
- ❌ logging inside tight loops.
- ✅ one log line per business event, with context.

## 3. Correlation ids (MDC)

```java
@Component
public class CorrelationFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        String id = Optional.ofNullable(req.getHeader("X-Request-Id")).orElse(UUID.randomUUID().toString());
        MDC.put("requestId", id);
        res.setHeader("X-Request-Id", id);
        try { chain.doFilter(req, res); } finally { MDC.clear(); }
    }
}
```
```yaml
logging.pattern.level: "%5p [%X{requestId}]"
```
Every log line of one request now shares the same id → easy to trace.

## 4. Structured (JSON) logs

```yaml
logging.structured.format.console: ecs     # or logstash
```

## 5. Actuator

```groovy
implementation 'org.springframework.boot:spring-boot-starter-actuator'
```
```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, info, metrics, prometheus
  endpoint:
    health:
      show-details: when-authorized
```

| Endpoint | Shows |
|---|---|
| `/actuator/health` | UP/DOWN + DB, disk, custom checks |
| `/actuator/info` | app version, git commit |
| `/actuator/metrics` | JVM, HTTP, DB pool metrics |
| `/actuator/prometheus` | metrics for Prometheus |
| `/actuator/loggers` | change log levels at runtime |

⚠️ Never expose all endpoints publicly (`env`, `heapdump` leak secrets). Secure them (month 6).

## 6. Custom health check and metrics

```java
@Component
public class PaymentProviderHealth implements HealthIndicator {
    @Override
    public Health health() {
        return provider.ping() ? Health.up().build()
                               : Health.down().withDetail("provider", "unreachable").build();
    }
}

@Service
public class CheckoutService {
    private final Counter ordersPlaced;
    public CheckoutService(MeterRegistry registry) {
        this.ordersPlaced = Counter.builder("shop.orders.placed").register(registry);
    }
    void place(...) { ...; ordersPlaced.increment(); }
}

@Timed("shop.checkout")   // with TimedAspect bean
```

Kubernetes probes: `/actuator/health/liveness` and `/actuator/health/readiness`.
