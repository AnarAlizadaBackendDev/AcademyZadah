## 1. Stereotype annotations

| Annotation | Layer | Extra |
|---|---|---|
| `@Component` | generic | |
| `@Service` | business logic | semantic |
| `@Repository` | data access | translates DB exceptions to `DataAccessException` |
| `@Controller` / `@RestController` | web | request handling |
| `@Configuration` | config class | holds `@Bean` methods |

## 2. @Bean: for classes you don't own

```java
@Configuration
public class AppConfig {

    @Bean
    public Clock clock() {
        return Clock.system(ZoneId.of("Asia/Baku"));
    }

    @Bean
    public RestClient currencyClient(RestClient.Builder builder) {
        return builder.baseUrl("https://api.rates.example").build();
    }

    @Bean
    public ObjectMapper objectMapper() {
        return JsonMapper.builder().findAndAddModules().build();
    }
}
```
Injecting a `Clock` instead of calling `LocalDate.now()` makes time-dependent code testable.

## 3. Bean scopes

| Scope | Instances |
|---|---|
| **singleton** (default) | one per application context |
| prototype | new instance every injection/lookup |
| request | one per HTTP request (web) |
| session | one per HTTP session (web) |

```java
@Component
@Scope("prototype")
public class ReportBuilder { ... }
```
⚠️ Singletons are shared by all threads → **must be stateless** (or thread-safe). Never store request data in fields of a `@Service`.

```java
@Service
public class CartService {
    private List<Item> items = new ArrayList<>();   // ❌ shared by ALL users!
}
```

## 4. Bean lifecycle

```
instantiate → inject dependencies → @PostConstruct → ready ... → @PreDestroy → destroyed
```
```java
@Component
public class RatesCache {
    private final Map<String, BigDecimal> rates = new ConcurrentHashMap<>();

    @PostConstruct
    void warmUp() { rates.putAll(loadRates()); }

    @PreDestroy
    void shutdown() { log.info("Cache shutting down"); }
}
```
Other hooks: `ApplicationRunner`/`CommandLineRunner` (after startup), `@EventListener(ApplicationReadyEvent.class)`.

## 5. Conditional beans

```java
@Bean
@ConditionalOnProperty(name = "notifications.sms.enabled", havingValue = "true")
public Notifier smsNotifier() { ... }

@Bean
@ConditionalOnMissingBean(Notifier.class)
public Notifier consoleNotifier() { ... }

@Bean
@Profile("dev")
public PaymentGateway fakeGateway() { ... }
```
This is exactly how Spring Boot auto-configuration works (next lesson).

## 6. Circular dependencies

`A` needs `B`, `B` needs `A` → Spring Boot fails at startup (since 2.6). It's a design smell: extract a third class or use events.

## 7. Application events (decoupling)

```java
public record OrderPlaced(Long orderId, String customerEmail) { }

@Service
class OrderService {
    private final ApplicationEventPublisher events;
    void place(Order o) {
        // save...
        events.publishEvent(new OrderPlaced(o.getId(), o.getEmail()));
    }
}

@Component
class EmailListener {
    @EventListener
    void on(OrderPlaced e) { sendConfirmation(e.customerEmail()); }
}
```
`@TransactionalEventListener(phase = AFTER_COMMIT)`: run only if the transaction committed.
