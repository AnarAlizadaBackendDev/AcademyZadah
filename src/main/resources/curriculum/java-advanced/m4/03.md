> **Goal:** understand what Spring Boot adds: starters, auto-configuration and packaging.
> **Duration:** 120 min

## 1. Spring vs Spring Boot

**Spring Framework**: DI container, web MVC, transactions, data access...: powerful but lots of configuration.
**Spring Boot**: opinionated defaults on top of Spring:
- **starters**: one dependency brings a coherent set of libraries,
- **auto-configuration**: beans configured automatically based on the classpath and properties,
- **embedded server** (Tomcat): run with `java -jar`,
- **production features** (Actuator).

## 2. Spring Initializr

start.spring.io → Gradle, Java 21, Spring Boot 3.x, group `az.academy`, artifact `shop`, dependencies: Spring Web, Spring Data JPA, PostgreSQL, Validation, Flyway, Actuator.

## 3. Project structure

```
shop/
├── build.gradle
└── src/main/java/az/academy/shop/
    ├── ShopApplication.java          ← @SpringBootApplication (root package!)
    ├── customer/                     ← package by FEATURE
    │   ├── Customer.java
    │   ├── CustomerRepository.java
    │   ├── CustomerService.java
    │   └── CustomerController.java
    ├── order/ ...
    └── common/ ...
src/main/resources/
    ├── application.yml
    └── db/migration/
```
`@SpringBootApplication` = `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan` (of its package and sub-packages: keep it in the root package).

Package by **feature** scales better than package by layer (`controllers/`, `services/`).

## 4. Starters

```groovy
implementation 'org.springframework.boot:spring-boot-starter-web'        // Spring MVC + Tomcat + Jackson
implementation 'org.springframework.boot:spring-boot-starter-data-jpa'   // Hibernate + Spring Data + Hikari
implementation 'org.springframework.boot:spring-boot-starter-validation'
testImplementation 'org.springframework.boot:spring-boot-starter-test'   // JUnit 5, Mockito, AssertJ
```
Versions are managed by the Spring Boot plugin (BOM): no version numbers needed.

## 5. Auto-configuration

Example: you add `spring-boot-starter-data-jpa` + PostgreSQL driver and set `spring.datasource.url` → Boot creates a `DataSource` (Hikari), `EntityManagerFactory`, `TransactionManager`, repositories...

It's all `@Configuration` classes with `@ConditionalOnClass`, `@ConditionalOnMissingBean`, `@ConditionalOnProperty`. **Your own bean always wins** over the auto-configured one.

See what was configured and why:
```bash
java -jar app.jar --debug          # CONDITIONS EVALUATION REPORT
```
or Actuator `/actuator/conditions`.

Exclude something:
```java
@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
```

## 6. Running and packaging

```bash
./gradlew bootRun
./gradlew bootJar          # build/libs/shop-0.0.1-SNAPSHOT.jar (fat jar with all deps)
java -jar build/libs/shop-0.0.1-SNAPSHOT.jar
./gradlew bootBuildImage   # OCI/Docker image with buildpacks
```

DevTools for automatic restart in development:
```groovy
developmentOnly 'org.springframework.boot:spring-boot-devtools'
```

## 7. First endpoint

```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public Map<String, String> hello(@RequestParam(defaultValue = "student") String name) {
        return Map.of("message", "Hello, " + name);
    }
}
```
`curl localhost:8080/hello?name=Anar` → `{"message":"Hello, Anar"}`

## 8. Hands-on

3. Define your own `DataSource` bean and see the auto-configured one back off.
4. Build the fat jar and run it from the terminal.
5. Move your month 3 entities/repositories into feature packages.
