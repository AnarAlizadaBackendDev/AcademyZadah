> **Goal:** understand proxies and AOP, and how `@Transactional` really works.
> **Duration:** 120 min

## 1. Cross-cutting concerns

Logging, timing, security checks, transactions, retries... are needed in many methods. Copy-pasting them everywhere is bad. **AOP** (Aspect-Oriented Programming) applies them **around** methods without changing the methods.

## 2. Proxies

When a bean needs AOP features, Spring injects a **proxy** instead of your object:

```
Controller ──▶ [Proxy of OrderService] ──▶ real OrderService
                 │ begin transaction
                 │ call real method
                 │ commit / rollback
```
- Interface-based: JDK dynamic proxy.
- Class-based: **CGLIB** subclass (default in Boot).

## 3. Writing an aspect

```groovy
implementation 'org.springframework.boot:spring-boot-starter-aop'
```
```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Timed { }

@Aspect
@Component
public class TimingAspect {
    private static final Logger log = LoggerFactory.getLogger(TimingAspect.class);

    @Around("@annotation(az.academy.shop.common.Timed)")
    public Object time(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.nanoTime();
        try {
            return pjp.proceed();
        } finally {
            log.info("{} took {} ms", pjp.getSignature().toShortString(), (System.nanoTime() - start) / 1_000_000);
        }
    }
}

@Service
public class ReportService {
    @Timed
    public Report monthly() { ... }
}
```

| Advice | Runs |
|---|---|
| `@Before` | before the method |
| `@AfterReturning` | after success |
| `@AfterThrowing` | after exception |
| `@After` | always after |
| `@Around` | wraps the call (most powerful) |

Pointcut examples: `execution(* az.academy.shop..*Service.*(..))`, `@annotation(...)`, `within(...)`.

## 4. How @Transactional works

```java
@Service
public class TransferService {
    @Transactional
    public void transfer(...) { ... }
}
```
The proxy: gets a connection → `BEGIN` → calls your method → `COMMIT`, or `ROLLBACK` on **RuntimeException/Error**.

### Rules and pitfalls
1. **Checked exceptions do NOT roll back** by default: `@Transactional(rollbackFor = Exception.class)`.
2. **Self-invocation bypasses the proxy:**
```java
public void a() { b(); }        // calls this.b(), NOT the proxy → no transaction!
@Transactional public void b() { ... }
```
3. Only **public** methods are proxied (Spring 6 also supports protected/package with CGLIB, but keep it public).
4. Catching the exception inside the method → no rollback (the proxy never sees it).

### Attributes
```java
@Transactional(readOnly = true)                       // optimisation, no dirty checking flush
@Transactional(propagation = Propagation.REQUIRES_NEW) // separate transaction (e.g. audit log)
@Transactional(isolation = Isolation.SERIALIZABLE)
@Transactional(timeout = 5)
```

| Propagation | Behaviour |
|---|---|
| `REQUIRED` (default) | join existing or create new |
| `REQUIRES_NEW` | suspend current, create new |
| `MANDATORY` | must run inside an existing one |
| `NOT_SUPPORTED` | run without transaction |

Typical pattern: class-level `@Transactional(readOnly = true)`, method-level `@Transactional` for writes.

## 5. Hands-on

1. `@Timed` aspect; apply to service methods; log durations.
2. An aspect that logs method arguments for `*Service` classes (mask fields named `password`, `cardNumber`!).
3. Demonstrate: checked exception doesn't roll back; fix with `rollbackFor`.
4. Demonstrate self-invocation; fix by moving the method to another bean.
5. `REQUIRES_NEW` audit log that survives a rollback of the main transaction.
