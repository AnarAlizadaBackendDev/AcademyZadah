## 1. Layered architecture

```
┌───────────────────────────┐
│ Controller (web)          │  HTTP ↔ DTOs, validation, status codes
├───────────────────────────┤
│ Service (application)     │  use cases, transactions, business rules
├───────────────────────────┤
│ Domain (entities, values) │  invariants, behaviour
├───────────────────────────┤
│ Repository (persistence)  │  data access
└───────────────────────────┘
```
Rules:
- Dependencies point **downwards**.
- Controllers don't access repositories directly (in non-trivial apps).
- Entities never leave the service layer as API responses → use **DTOs**.

## 2. DTOs vs entities

Why not return entities from controllers?
- Lazy-loading exceptions and N+1 during JSON serialization.
- Exposes internal fields (password hashes, internal flags).
- API changes whenever the DB changes.
- Infinite recursion with bidirectional relations.

```java
public record ProductResponse(Long id, String name, BigDecimal price, String category) {
    public static ProductResponse from(Product p) {
        return new ProductResponse(p.getId(), p.getName(), p.getPrice(), p.getCategory().getName());
    }
}
public record CreateProductRequest(@NotBlank String sku, @NotBlank String name, @Positive BigDecimal price, Long categoryId) { }
```

## 3. Rich domain vs anemic

```java
// anemic: logic in services, entity is just getters/setters
order.setStatus(OrderStatus.PAID);

// rich: entity protects its rules ✅
public void markPaid(Payment payment) {
    if (status != OrderStatus.NEW) throw new IllegalStateException("Order " + id + " is " + status);
    if (payment.amount().compareTo(total) != 0) throw new PaymentMismatchException(id);
    this.status = OrderStatus.PAID;
    this.paidAt = payment.paidAt();
}
```

## 4. Example flow: place order

```java
@RestController
@RequestMapping("/api/orders")
class OrderController {
    private final OrderService orders;
    @PostMapping
    ResponseEntity<OrderResponse> place(@Valid @RequestBody PlaceOrderRequest req) {
        OrderResponse created = orders.place(req);
        return ResponseEntity.created(URI.create("/api/orders/" + created.id())).body(created);
    }
}

@Service
@Transactional
class OrderService {
    OrderResponse place(PlaceOrderRequest req) {
        Customer customer = customers.findById(req.customerId()).orElseThrow(() -> new NotFoundException("customer", req.customerId()));
        Order order = Order.create(customer);
        for (var line : req.items()) {
            Product product = products.findForUpdate(line.productId()).orElseThrow(...);
            product.reserve(line.quantity());
            order.addItem(product, line.quantity());
        }
        orders.save(order);
        events.publishEvent(new OrderPlaced(order.getId()));
        return OrderResponse.from(order);
    }
}
```

## 6. 🏁 Month 4 Project: Layered Shop Backend

### Requirements
1. Features: catalog (categories, products), customers, cart, orders, inventory.
2. Layers: controller → service → domain → repository, packaged by feature.
3. DTOs for all inputs/outputs; validation annotations on requests.
4. Rich domain methods (`Order.addItem`, `markPaid`, `cancel`, `Product.reserve`).
5. Transactions on services; read-only by default.
6. Configuration properties, dev/prod profiles, Flyway migrations.
7. Logging with correlation ids, Actuator health + custom metrics.
8. At least 30 tests (unit for domain + `@DataJpaTest` for repositories).
9. README with architecture diagram.
