> **Goal:** design tables with correct data types and constraints.
> **Duration:** 120 min

## 1. DDL: Data Definition Language

`CREATE`, `ALTER`, `DROP`, `TRUNCATE`: they change the **structure**.

## 2. PostgreSQL data types

| Type | Use |
|---|---|
| `SMALLINT`, `INTEGER`, `BIGINT` | whole numbers (ids → `BIGINT`) |
| `NUMERIC(19,4)` | **money**: exact decimals |
| `REAL`, `DOUBLE PRECISION` | scientific values (not money!) |
| `VARCHAR(n)`, `TEXT` | strings |
| `BOOLEAN` | true/false |
| `DATE`, `TIME`, `TIMESTAMP` | without zone |
| `TIMESTAMPTZ` | **exact moments** (store in UTC) |
| `UUID` | global unique ids |
| `JSONB` | semi-structured data |

## 3. Constraints

```sql
CREATE TABLE customers (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    full_name   VARCHAR(120) NOT NULL,
    email       VARCHAR(160) NOT NULL UNIQUE,
    birth_date  DATE CHECK (birth_date > '1900-01-01'),
    status      VARCHAR(20) NOT NULL DEFAULT 'ACTIVE'
                CHECK (status IN ('ACTIVE', 'BLOCKED', 'CLOSED')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE accounts (
    id           BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id  BIGINT NOT NULL REFERENCES customers (id),
    iban         CHAR(28) NOT NULL UNIQUE,
    currency     CHAR(3) NOT NULL,
    balance      NUMERIC(19, 4) NOT NULL DEFAULT 0 CHECK (balance >= 0),
    opened_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

| Constraint | Guarantees |
|---|---|
| `PRIMARY KEY` | unique + not null identifier |
| `FOREIGN KEY` / `REFERENCES` | the referenced row exists |
| `UNIQUE` | no duplicates |
| `NOT NULL` | value required |
| `CHECK` | custom rule |
| `DEFAULT` | value if not provided |

> The database is the **last line of defence**. Even if Java code has a bug, constraints keep data valid.

## 4. Foreign key actions

```sql
customer_id BIGINT REFERENCES customers (id) ON DELETE CASCADE      -- delete children
customer_id BIGINT REFERENCES customers (id) ON DELETE RESTRICT     -- forbid (default-like)
customer_id BIGINT REFERENCES customers (id) ON DELETE SET NULL
```
In financial systems we rarely delete: use a `status` column ("soft delete").

## 5. ALTER and DROP

```sql
ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
ALTER TABLE customers ALTER COLUMN phone SET NOT NULL;
ALTER TABLE customers RENAME COLUMN full_name TO name;
ALTER TABLE accounts ADD CONSTRAINT chk_currency CHECK (currency IN ('AZN', 'USD', 'EUR'));
ALTER TABLE customers DROP COLUMN phone;
DROP TABLE IF EXISTS temp_data;
TRUNCATE TABLE logs;          -- delete all rows fast
```
In real projects, every schema change goes through **migrations** (Flyway/Liquibase, month 3).

## 6. Identity vs sequences vs UUID

```sql
id BIGINT GENERATED ALWAYS AS IDENTITY        -- modern standard
id BIGSERIAL                                  -- older PostgreSQL shortcut
id UUID DEFAULT gen_random_uuid()             -- distributed systems, public ids
```

## 7. Naming conventions

- `snake_case`, plural or singular consistently (`customers` or `customer`).
- PK `id`, FK `<table>_id`.
- Constraint names: `uk_customers_email`, `fk_accounts_customer`.

## 8. Hands-on: library schema

Create tables with all constraints:
- `authors(id, name, country)`
- `books(id, isbn UNIQUE, title, author_id FK, published_year CHECK, copies CHECK >= 0)`
- `members(id, name, email UNIQUE, type CHECK IN ('STUDENT','REGULAR'), joined_at)`
- `loans(id, book_id FK, member_id FK, loaned_at, due_date, returned_at, CHECK due_date > loaned_at)`

Try to insert invalid data and read each error message.

## 9. Interview corner

- `DELETE` vs `TRUNCATE` vs `DROP`?
