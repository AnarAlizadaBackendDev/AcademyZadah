## 1. Test suite architecture

```
src/test/java/az/academy/shop/
├── support/                  builders, TestcontainersConfig, base classes, security helpers
├── order/
│   ├── OrderTest.java                    unit (domain)
│   ├── CheckoutServiceTest.java          unit (Mockito)
│   ├── OrderControllerTest.java          @WebMvcTest
│   ├── OrderRepositoryTest.java          @DataJpaTest + Testcontainers
│   └── OrderApiIT.java                   RestAssured journey
└── ArchitectureTest.java
```
Naming: `*Test` for fast tests, `*IT` for integration (separate Gradle task if needed).

```groovy
tasks.register('integrationTest', Test) {
    useJUnitPlatform { includeTags 'integration' }
}
test { useJUnitPlatform { excludeTags 'integration' } }
```

## 2. Flaky tests

Causes: time, randomness, shared data, test order, async without waiting, real network.
Policy: a flaky test is a **bug**: quarantine (`@Disabled` with ticket) and fix quickly.

## 3. CI pipeline preview (month 9)

```yaml
- run: ./gradlew spotlessCheck test integrationTest jacocoTestReport
```
Every PR runs the whole suite; merge only when green.

## 4. 🏁 Month 7 Project: Complete Test Suite

### Requirements (for your shop project)
1. `TESTING.md`: strategy and how to run each level.
2. Domain unit tests with builders and parameterized tests: order state machine, pricing, stock.
3. Service tests with Mockito: checkout, payment, refunds/cancel.
4. Slice tests: all controllers (validation, errors, security), repositories (custom queries).
5. Testcontainers integration tests: PostgreSQL + WireMock payment provider.
6. ≥ 3 journey tests with RestAssured (customer, admin, failure path).
7. Concurrency test for stock reservation.
8. JaCoCo ≥ 80% branch coverage on domain + services; PIT report for domain.
9. Sonar quality gate passing; Spotless enforced.
10. Whole suite < 3 minutes on a laptop.

### Evaluation
| Criteria | Points |

| Test code quality (readable, no flakiness) | 20 |
