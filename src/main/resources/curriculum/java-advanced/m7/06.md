## 1. API-level tests

Testing through HTTP like a real client catches serialization, security, error mapping and integration bugs together.

### RestAssured
```groovy
testImplementation 'io.rest-assured:rest-assured'
```
```java
@SpringBootTest(webEnvironment = RANDOM_PORT)
@Import(TestcontainersConfig.class)
class OrderApiTest {

    @LocalServerPort int port;

    @BeforeEach
    void setUp() { RestAssured.port = port; }

    @Test
    void customerFlow() {
        String token = login("leyla@mail.az", "Secret12345");

        Integer orderId =
            given().auth().oauth2(token).contentType(ContentType.JSON)
                   .body("""
                         {"items": [{"productId": 1, "quantity": 2}]}
                         """)
            .when().post("/api/v1/orders")
            .then().statusCode(201)
                   .header("Location", containsString("/api/v1/orders/"))
                   .body("status", equalTo("NEW"))
                   .body("total", equalTo("4800.00"))
                   .extract().path("id");

        given().auth().oauth2(token)
        .when().get("/api/v1/orders/{id}", orderId)
        .then().statusCode(200).body("items", hasSize(1));
    }

    @Test
    void otherCustomerGets404() {
        String other = login("murad@mail.az", "Secret12345");
        given().auth().oauth2(other).when().get("/api/v1/orders/{id}", existingOrderOfLeyla())
               .then().statusCode(404);
    }
}
```

## 2. Testing scenarios, not endpoints

Write tests as **user journeys**:
1. Register → login → browse → add to cart → place order → pay → see order PAID.
2. Admin: create product → customer buys → admin sees report.
3. Failure journeys: payment declined → order stays NEW → retry succeeds with new idempotency key.

## 3. Contract testing (between microservices)

Problem: the orders-service changes a field name; the notifications-service (consumer) breaks in production.

**Consumer-driven contracts**:
- The consumer writes a contract: "when I call `GET /orders/1`, I expect `id`, `status`, `customerEmail`".
- The provider's build verifies it satisfies all consumer contracts.

Tools: **Spring Cloud Contract** (Groovy/YAML contracts, generates provider tests and consumer stubs) or **Pact**.

```groovy
// contracts/shouldReturnOrder.groovy
Contract.make {
    request { method 'GET'; url '/api/v1/orders/1' }
    response {
        status 200
        headers { contentType applicationJson() }
        body(id: 1, status: 'PAID', customerEmail: 'leyla@mail.az')
    }
}
```

Simpler alternative: OpenAPI spec diff in CI (`openapi-diff`) to detect breaking changes.

## 4. Testing webhooks and async flows

```java
await().atMost(Duration.ofSeconds(5))
       .untilAsserted(() -> assertThat(orders.findById(id).orElseThrow().getStatus()).isEqualTo(PAID));
```
