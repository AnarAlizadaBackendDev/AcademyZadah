> **Goal:** write reliable integration tests with real dependencies using Testcontainers.
> **Duration:** 120 min

## 1. Why not H2 for tests?

H2 ≠ PostgreSQL: different SQL dialect, no `FOR UPDATE SKIP LOCKED`, JSONB, window function differences... Tests pass, production fails. **Testcontainers** starts real PostgreSQL/Kafka/Redis in Docker for tests.

## 2. Setup

```groovy
testImplementation 'org.springframework.boot:spring-boot-testcontainers'
testImplementation 'org.testcontainers:junit-jupiter'
testImplementation 'org.testcontainers:postgresql'
```

```java
@TestConfiguration(proxyBeanMethods = false)
public class TestcontainersConfig {
    @Bean
    @ServiceConnection                                  // Spring Boot 3.1+: auto-configures the datasource
    PostgreSQLContainer<?> postgres() {
        return new PostgreSQLContainer<>("postgres:17-alpine");
    }
}

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@Import(TestcontainersConfig.class)
class CheckoutIntegrationTest {

    @Autowired TestRestTemplate http;
    @Autowired ProductRepository products;

    @Test
    void placesOrderAndReducesStock() {
        Product p = products.save(new Product("SKU1", "Laptop", new BigDecimal("2400"), 5));

        ResponseEntity<OrderResponse> res = http.postForEntity("/api/v1/orders",
                new PlaceOrderRequest(1L, List.of(new OrderLineRequest(p.getId(), 2))), OrderResponse.class);

        assertThat(res.getStatusCode()).isEqualTo(HttpStatus.CREATED);
        assertThat(products.findById(p.getId()).orElseThrow().getStock()).isEqualTo(3);
    }
}
```
Flyway migrations run against the container → tests also verify your migrations.

## 3. Reusing containers for speed

- Same `@Import(TestcontainersConfig.class)` everywhere → one Spring context and container reused across test classes.
- Singleton container pattern (static container started once).
- Local dev: `testcontainers.reuse.enable=true` in `~/.testcontainers.properties` + `.withReuse(true)`.

## 4. Other containers

```java
@Bean @ServiceConnection
KafkaContainer kafka() { return new KafkaContainer(DockerImageName.parse("apache/kafka:3.8.0")); }

@Bean @ServiceConnection(name = "redis")
GenericContainer<?> redis() { return new GenericContainer<>("redis:7-alpine").withExposedPorts(6379); }
```
WireMock container or `wiremock-spring-boot` for external HTTP APIs.

## 5. Test data management

- Each test creates its own data (builders/repositories).
- Clean between tests: `@Sql(scripts = "/cleanup.sql", executionPhase = AFTER_TEST_METHOD)` or truncate tables in `@AfterEach`.
- Avoid depending on data created by other tests.

## 6. Running the app locally with containers

```java
public class TestShopApplication {
    public static void main(String[] args) {
        SpringApplication.from(ShopApplication::main).with(TestcontainersConfig.class).run(args);
    }
}
```
`./gradlew bootTestRun`: the app starts with a throwaway PostgreSQL: no local DB setup needed.

## 7. Concurrency integration test

```java
@Test
void onlyAvailableStockIsSold() throws Exception {
    Product p = products.save(new Product("SKU", "Phone", new BigDecimal("500"), 10));
    try (var pool = Executors.newFixedThreadPool(20)) {
        List<Future<HttpStatusCode>> results = IntStream.range(0, 50)
                .mapToObj(i -> pool.submit(() -> placeOrder(p.getId(), 1).getStatusCode()))
                .toList();
        long created = results.stream().filter(f -> get(f) == HttpStatus.CREATED).count();
        assertThat(created).isEqualTo(10);
    }
    assertThat(products.findById(p.getId()).orElseThrow().getStock()).isZero();
}
```
This can only be trusted with the **real** database.
