> **Goal:** isolate units with Mockito mocks, stubs and verification.
> **Duration:** 120 min

## 1. When to mock

The `CheckoutService` uses a repository, a payment client and an event publisher. To test its **logic** quickly without a DB or network, replace collaborators with mocks.

## 2. Basics

```java
@ExtendWith(MockitoExtension.class)
class CheckoutServiceTest {

    @Mock OrderRepository orders;
    @Mock PaymentClient payments;
    @Mock ApplicationEventPublisher events;
    @InjectMocks CheckoutService checkout;

    @Test
    void paysAndMarksOrderPaid() {
        Order order = anOrder().withTotal("100.00").build();
        when(orders.findById(1L)).thenReturn(Optional.of(order));
        when(payments.charge(any(), eq(new BigDecimal("100.00")))).thenReturn(new ChargeResult("P-1", true));

        checkout.pay(1L, "key-1");

        assertThat(order.getStatus()).isEqualTo(OrderStatus.PAID);
        verify(events).publishEvent(any(OrderPaid.class));
    }
}
```

## 3. Stubbing

```java
when(repo.findById(42L)).thenReturn(Optional.empty());
when(client.charge(any(), any())).thenThrow(new PaymentDeclinedException("insufficient funds"));
when(rates.get("USD")).thenReturn(new BigDecimal("1.70"), new BigDecimal("1.71"));   // consecutive calls
when(repo.save(any(Order.class))).thenAnswer(inv -> inv.getArgument(0));            // return what was passed
doThrow(new RuntimeException()).when(notifier).send(any());                          // void methods
```
Argument matchers: `any()`, `eq(x)`, `anyString()`, `argThat(o -> o.getTotal().signum() > 0)`. If one argument uses a matcher, all must.

## 4. Verification

```java
verify(notifier).send(eq("+994501234567"), contains("confirmed"));
verify(payments, never()).charge(any(), any());
verify(repo, times(2)).save(any());
verifyNoMoreInteractions(payments);
InOrder inOrder = inOrder(stock, payments);
inOrder.verify(stock).reserve(any());
inOrder.verify(payments).charge(any(), any());
```

## 5. Argument captors

```java
@Captor ArgumentCaptor<Order> orderCaptor;

checkout.place(request);

verify(orders).save(orderCaptor.capture());
Order saved = orderCaptor.getValue();
assertThat(saved.getItems()).hasSize(2);
assertThat(saved.total()).isEqualByComparingTo("150.00");
```

## 6. Spies (use rarely)

```java
List<String> list = spy(new ArrayList<>());
list.add("a");
verify(list).add("a");
```

## 7. Mocking pitfalls

- ❌ Mocking everything, including value objects and the class under test.
- ❌ Tests that just repeat the implementation ("verify called X then Y"): they break on every refactor.
- ❌ Mocking types you don't own deeply (e.g. `RestClient` chains): wrap them in your own `PaymentClient` interface and mock that.
- ✅ Assert **outcomes** (state, return values) first; verify interactions only for important side effects (payment charged, email sent).
- Strict stubs (default with `MockitoExtension`) fail on unused stubbing: keeps tests clean.
