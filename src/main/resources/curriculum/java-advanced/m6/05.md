> **Goal:** secure stateless APIs with JWT access and refresh tokens.
> **Duration:** 120 min

## 1. Why tokens?

Mobile apps and SPAs call APIs across many servers. Server sessions need sticky sessions or shared storage. A **token** carries the identity with every request: the server stays **stateless**.

## 2. JWT structure

```
eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiI0MiIsInJvbGVzIjpbIkNVU1RPTUVSIl0sImV4cCI6MTc2MDUzMTIwMH0.signature
      header                          payload (claims)                                       signature
```
```json
{ "alg": "RS256" }
{ "sub": "42", "roles": ["CUSTOMER"], "iat": 1760530300, "exp": 1760531200, "iss": "shop" }
```
- Base64URL-encoded: **anyone can read it**: never put secrets inside.
- The **signature** proves it wasn't modified (HMAC secret or RSA private key).

## 3. Issuing tokens (Spring Security's built-in support)

```groovy
implementation 'org.springframework.boot:spring-boot-starter-oauth2-resource-server'
```
```java
@Service
public class TokenService {
    private final JwtEncoder encoder;

    public String accessToken(AppUserPrincipal user) {
        Instant now = Instant.now();
        JwtClaimsSet claims = JwtClaimsSet.builder()
                .issuer("shop")
                .subject(user.getId().toString())
                .issuedAt(now)
                .expiresAt(now.plus(15, ChronoUnit.MINUTES))          // short-lived!
                .claim("roles", user.getAuthorities().stream().map(GrantedAuthority::getAuthority).toList())
                .build();
        return encoder.encode(JwtEncoderParameters.from(claims)).getTokenValue();
    }
}

@Bean JwtEncoder jwtEncoder(RSAKey key) { return new NimbusJwtEncoder(new ImmutableJWKSet<>(new JWKSet(key))); }
@Bean JwtDecoder jwtDecoder(RSAKey key) throws JOSEException { return NimbusJwtDecoder.withPublicKey(key.toRSAPublicKey()).build(); }
```

## 4. Validating tokens

```java
http
    .csrf(c -> c.disable())
    .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
    .authorizeHttpRequests(a -> a
        .requestMatchers("/api/v1/auth/**").permitAll()
        .anyRequest().authenticated())
    .oauth2ResourceServer(o -> o.jwt(j -> j.jwtAuthenticationConverter(rolesConverter())));
```
Client:
```
GET /api/v1/orders
Authorization: Bearer eyJhbGciOi...
```
Spring verifies signature, `exp`, issuer → builds the `Authentication`.

## 5. Refresh tokens

| Token | Lifetime | Stored | Used for |
|---|---|---|---|
| Access (JWT) | 5–15 min | memory of the client | every API call |
| Refresh (random, opaque) | days–weeks | DB (hashed) + client secure storage | get a new access token |

```
POST /api/v1/auth/refresh { "refreshToken": "..." }
→ new access token + NEW refresh token (rotation); old refresh token invalidated
```
Rotation + reuse detection: if an old refresh token is used again → revoke the whole family (stolen token).

## 6. Revocation (logout)

JWTs can't be "deleted". Options:
- short access token lifetime + revoke refresh token on logout ✅
- deny-list of `jti` (token ids) in Redis until expiry, for emergencies
- token version per user (`tv` claim) checked on each request

## 7. Security rules for JWT

- Use RS256/ES256 (asymmetric) when other services must verify tokens.
- Validate `exp`, `iss`, `aud`; reject `alg: none`.
- Keep payload small; no personal data.
- HTTPS only.
- Browser apps: avoid `localStorage` for tokens if possible (XSS); consider HttpOnly cookies or a BFF pattern.
