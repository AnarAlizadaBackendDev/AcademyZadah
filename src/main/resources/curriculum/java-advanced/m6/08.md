> **Goal:** harden the shop API end to end: the month 6 security project.
> **Duration:** 120 min + project week

## 1. Security checklist

**Authentication**
- [ ] BCrypt/Argon2 passwords, length policy
- [ ] Generic login errors, lockout, rate limits
- [ ] Short-lived access tokens, refresh rotation, logout

**Authorization**
- [ ] Deny by default (`anyRequest().authenticated()`)
- [ ] Roles/permissions on URLs **and** services
- [ ] Ownership checks on every customer resource (no IDOR)

**Input & output**
- [ ] Validation on all inputs; parameterized queries only
- [ ] No entities/internal fields in responses
- [ ] Error responses without internals

**Transport & config**
- [ ] HTTPS, HSTS, security headers, strict CORS
- [ ] Secrets from environment; none in Git
- [ ] Actuator locked down

**Monitoring**
- [ ] Audit log: logins, failed logins, password changes, payments, admin actions
- [ ] Alerts on suspicious activity

## 2. Audit logging

```java
public record AuditEvent(Instant at, Long userId, String action, String target, String ip, boolean success) { }

@Component
class SecurityAuditListener {
    @EventListener
    void loginSuccess(AuthenticationSuccessEvent e) { audit.record("LOGIN", e.getAuthentication().getName(), true); }
    @EventListener
    void loginFailure(AbstractAuthenticationFailureEvent e) { audit.record("LOGIN", e.getAuthentication().getName(), false); }
}
```
Audit logs are append-only, stored separately, retained per regulation.

## 3. Security testing

- Unit/integration tests for every access rule.
- **OWASP ZAP** baseline scan against your running API (Docker):
```bash
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-api-scan.py -t http://host.docker.internal:8080/v3/api-docs -f openapi
```
- Manual tests: change ids in URLs, tamper JWTs, oversized payloads, special characters.

## 4. 🏁 Month 6 Project: Secured Shop API

### Requirements
1. Users: register, login, refresh (rotation + reuse detection), logout, change password, lockout.
2. Roles: CUSTOMER, MANAGER, ADMIN with permissions; URL + method security.
3. Ownership checks for orders, cart, addresses, payments.
4. JWT (own issuer) **or** Keycloak via profile.
5. CORS, CSRF reasoning, headers, rate limiting on auth endpoints.
6. Audit log table + admin endpoint to search audit events.
7. Security test matrix (≥ 30 tests) + ZAP baseline report (fix or justify findings).
8. `SECURITY.md`: threat model, controls, how to report vulnerabilities.

### Evaluation
| Criteria | Points |
|---|---|
| Authentication flows | 20 |
| Authorization & ownership | 25 |
| Hardening (headers, CORS, rate limit, secrets) | 15 |
| Audit & monitoring | 10 |
| Tests & ZAP | 20 |
| Documentation | 10 |

## 5. Interview mock

- Walk me through what happens from login to calling `/orders` with a JWT.
- How would you secure a payment webhook?
- A token was stolen: what limits the damage, what do you do?
