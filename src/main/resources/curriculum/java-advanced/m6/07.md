## 1. CORS

Browsers block JavaScript from calling an API on another origin (scheme + host + port) unless the API allows it.

```
Frontend: https://shop.az      →   API: https://api.shop.az   (different origin)
Browser sends preflight: OPTIONS /api/v1/orders
  Origin: https://shop.az
  Access-Control-Request-Method: POST
API must answer:
  Access-Control-Allow-Origin: https://shop.az
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE
  Access-Control-Allow-Headers: Authorization, Content-Type
```

```java
@Bean
CorsConfigurationSource corsConfigurationSource(@Value("${shop.cors.origins}") List<String> origins) {
    CorsConfiguration cfg = new CorsConfiguration();
    cfg.setAllowedOrigins(origins);                              // explicit list, never "*" with credentials
    cfg.setAllowedMethods(List.of("GET", "POST", "PUT", "PATCH", "DELETE"));
    cfg.setAllowedHeaders(List.of("Authorization", "Content-Type", "Idempotency-Key"));
    cfg.setMaxAge(3600L);
    var source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/api/**", cfg);
    return source;
}
// and http.cors(Customizer.withDefaults());
```
CORS is **not** a security control for your API against attackers (curl ignores it); it protects users' browsers.

## 2. CSRF

Attack: a user is logged in to `bank.az` (session cookie). A malicious site makes the browser submit `POST bank.az/transfer`: the cookie is sent automatically.

Protection:
- **Cookie/session-based apps** (forms, like this academy website): CSRF tokens (Spring enables them by default), `SameSite=Lax/Strict` cookies.
- **Token-based APIs** (Bearer header): the browser doesn't attach the header automatically → CSRF not applicable → disable CSRF **only** for these stateless APIs.

## 3. Security headers

```java
http.headers(h -> h
    .contentSecurityPolicy(csp -> csp.policyDirectives("default-src 'self'; frame-ancestors 'none'"))
    .httpStrictTransportSecurity(hsts -> hsts.includeSubDomains(true).maxAgeInSeconds(31536000))
    .frameOptions(f -> f.deny())
    .referrerPolicy(r -> r.policy(ReferrerPolicyHeaderWriter.ReferrerPolicy.NO_REFERRER)));
```
| Header | Protects against |
|---|---|
| `Strict-Transport-Security` | HTTPS downgrade |
| `Content-Security-Policy` | XSS, clickjacking |
| `X-Frame-Options` | clickjacking |
| `X-Content-Type-Options: nosniff` | MIME sniffing |

Check with securityheaders.com.

## 4. Rate limiting

Protect login, OTP and expensive endpoints: Bucket4j, gateway rate limiting, or Redis counters.
```java
Bucket bucket = Bucket.builder().addLimit(Bandwidth.simple(5, Duration.ofMinutes(1))).build();
if (!bucket.tryConsume(1)) throw new TooManyRequestsException();   // 429
```

## 5. Secrets management

| ❌ | ✅ |
|---|---|
| secrets in Git (even in history!) | environment variables |
| same secret in all environments | different per environment |
| secrets in logs | masking |
| long-lived static keys | rotation |

Tools: HashiCorp Vault, GCP Secret Manager, AWS Secrets Manager, Kubernetes Secrets (+ sealed-secrets), Railway/Heroku config vars. Scan repos with **gitleaks**. If a secret leaks: **rotate immediately**, then clean history.
