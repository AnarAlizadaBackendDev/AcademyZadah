> **Goal:** document APIs with OpenAPI and Swagger UI.
> **Duration:** 120 min

## 1. Why documentation?

Frontend, mobile and partner teams integrate with your API. Without accurate docs, they guess, and integration takes weeks. **OpenAPI** is the standard machine-readable API description (formerly Swagger).

## 2. springdoc-openapi

```groovy
implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui:2.6.0'
```
Run the app:
- `http://localhost:8080/swagger-ui.html`: interactive UI
- `http://localhost:8080/v3/api-docs`: JSON spec

Generated automatically from controllers, DTOs and validation annotations.

## 3. Enriching docs

```java
@Configuration
public class OpenApiConfig {
    @Bean
    OpenAPI shopApi() {
        return new OpenAPI()
            .info(new Info().title("Shop API").version("v1")
                  .description("Online shop backend: catalog, cart, orders, payments")
                  .contact(new Contact().name("Anar Alizada").email("...")))
            .components(new Components().addSecuritySchemes("bearer",
                  new SecurityScheme().type(SecurityScheme.Type.HTTP).scheme("bearer").bearerFormat("JWT")));
    }
}

@Tag(name = "Orders", description = "Place and manage orders")
@RestController
@RequestMapping("/api/v1/orders")
class OrderController {

    @Operation(summary = "Place an order", description = "Reserves stock and creates an order in NEW status")
    @ApiResponse(responseCode = "201", description = "Order created")
    @ApiResponse(responseCode = "409", description = "Insufficient stock",
                 content = @Content(schema = @Schema(implementation = ProblemDetail.class)))
    @PostMapping
    ResponseEntity<OrderResponse> place(@Valid @RequestBody PlaceOrderRequest request) { ... }
}

public record PlaceOrderRequest(
        @Schema(description = "Customer id", example = "7") @NotNull Long customerId,
        @Schema(description = "Order lines") @NotEmpty List<@Valid OrderLineRequest> items) { }
```

## 4. Hide or group

```java
@Hidden                     // internal endpoint
```
```yaml
springdoc:
  swagger-ui:
    path: /docs
  paths-to-match: /api/**
```
Disable Swagger UI in production or protect it.

## 5. API-first vs code-first

| Code-first (springdoc) | API-first |
|---|---|
| write code → spec generated | write `openapi.yaml` → generate code (openapi-generator) |
| fast for one team | contract agreed before coding; parallel work |

Many banks/fintechs use API-first for partner APIs.

## 6. Generating clients

```bash
openapi-generator-cli generate -i http://localhost:8080/v3/api-docs -g typescript-fetch -o client-ts
```
Frontend gets a typed client for free.

## 7. Hands-on

1. Add springdoc; explore the generated UI.
2. Document all order and payment endpoints with summaries, examples and error responses.
3. Add the bearer security scheme (used in month 6).
4. Export the spec and generate a TypeScript or Java client.
