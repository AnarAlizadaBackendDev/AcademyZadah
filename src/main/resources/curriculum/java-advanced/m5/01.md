> **Goal:** design clean REST APIs using HTTP correctly.
> **Duration:** 120 min

## 1. HTTP basics

```
POST /api/orders HTTP/1.1
Host: shop.az
Content-Type: application/json
Authorization: Bearer eyJ...

{"customerId": 7, "items": [{"productId": 3, "quantity": 2}]}
```
```
HTTP/1.1 201 Created
Location: /api/orders/1024
Content-Type: application/json

{"id": 1024, "status": "NEW", "total": 89.90}
```
A request = **method + URL + headers + body**. A response = **status + headers + body**.

## 2. REST principles

- **Resources** identified by URLs (`/customers/7/orders`).
- **Representations** (JSON) of resources.
- Standard **methods** with standard semantics.
- **Stateless**: every request carries all info needed (e.g. token).

## 3. Methods

| Method | Meaning | Safe | Idempotent |
|---|---|---|---|
| GET | read | ✅ | ✅ |
| POST | create / action | ❌ | ❌ |
| PUT | replace whole resource | ❌ | ✅ |
| PATCH | partial update | ❌ | ❌ (usually) |
| DELETE | delete | ❌ | ✅ |

**Idempotent** = calling it N times has the same effect as once. Why it matters: clients and proxies retry on timeouts.

## 4. Status codes

| Code | When |
|---|---|
| 200 OK | successful GET/PUT/PATCH |
| 201 Created | POST created a resource (+ `Location` header) |
| 204 No Content | successful DELETE / no body |
| 400 Bad Request | validation errors, malformed JSON |
| 401 Unauthorized | not authenticated |
| 403 Forbidden | authenticated but not allowed |
| 404 Not Found | resource doesn't exist |
| 409 Conflict | duplicate / version conflict / invalid state |
| 422 Unprocessable Entity | business rule violation (some teams) |
| 429 Too Many Requests | rate limit |
| 500 Internal Server Error | unexpected bug |
| 503 Service Unavailable | dependency down / maintenance |

## 5. URL design

```
✅ GET    /api/products?category=laptops&page=0&size=20&sort=price,asc
✅ GET    /api/products/42
✅ POST   /api/products
✅ PUT    /api/products/42
✅ DELETE /api/products/42
✅ GET    /api/customers/7/orders
✅ POST   /api/orders/1024/cancel        (action that is not CRUD)
❌ GET    /api/getAllProducts
❌ POST   /api/products/delete/42
❌ GET    /api/product                  (use plural nouns)
```
- Nouns, plural, lowercase, kebab-case (`/payment-links`).
- Filters, sorting, pagination as **query parameters**.
- Versioning: `/api/v1/...` (lesson 5).

## 6. JSON conventions

```json
{
  "id": 1024,
  "status": "PAID",
  "total": { "amount": "89.90", "currency": "AZN" },
  "createdAt": "2026-10-15T10:15:30Z",
  "items": [ { "productId": 3, "quantity": 2 } ]
}
```
- camelCase fields, ISO-8601 dates in UTC, money as string/decimal + currency.
- Consistent error format (lesson 4).

## 7. Tools
