## 1. REST API quality checklist

- [ ] Resource-oriented URLs, correct methods and status codes
- [ ] DTOs, never entities, in requests/responses
- [ ] Validation on all inputs
- [ ] Consistent ProblemDetail errors with codes
- [ ] Pagination with limits, whitelisted sorting
- [ ] Idempotency for payment/creation endpoints where clients may retry
- [ ] Timeouts and retries for outgoing calls
- [ ] OpenAPI documentation
- [ ] Versioned base path `/api/v1`
- [ ] Correlation id in logs and error responses
- [ ] Tests for happy paths and error cases

## 2. Idempotent POST implementation

```java
@PostMapping("/api/v1/orders/{id}/pay")
public PaymentResponse pay(@PathVariable Long id, @RequestHeader("Idempotency-Key") @NotBlank String key) {
    return payments.findByIdempotencyKey(key)
                   .map(PaymentResponse::from)
                   .orElseGet(() -> paymentService.pay(id, key));
}
```
DB unique constraint on `idempotency_key` protects against two concurrent identical requests.

## 3. 🏁 Month 5 Project: Shop REST API (or Booking API)

Choose: **Shop** (continue your project) or **Booking** (hotel/doctor appointments).

### Shop requirements
1. Public catalog: categories, products, search (filters, sorting, paging).
2. Customers & addresses.
3. Cart: add/update/remove items, view totals.
4. Orders: place from cart (stock reservation), get, list my orders (cursor pagination), cancel (only NEW/PAID with rules).
5. Payments: pay order via mock provider with idempotency key; webhook endpoint `POST /api/v1/payments/webhook` for provider callbacks (verify a shared secret header).
6. Price in other currencies via a rates client with cache fallback.
7. All checklist items above.

### Booking alternative
Resources, availability slots, bookings with no double-booking (locking), cancellation rules, notifications.

### Deliverables
- Code on GitHub, OpenAPI spec, Postman collection.
- README: how to run (Docker Compose with Postgres + WireMock), architecture, error codes.
- ≥ 40 tests: domain unit tests, `@WebMvcTest` controller tests, integration tests.
