> **Goal:** return consistent, helpful error responses with `@RestControllerAdvice` and ProblemDetail.
> **Duration:** 120 min

## 1. The problem

By default errors leak stack traces or return inconsistent shapes. Clients (mobile apps, frontends, partners) need a **predictable error format**.

## 2. ProblemDetail (RFC 9457)

```json
{
  "type": "https://shop.az/errors/insufficient-stock",
  "title": "Insufficient stock",
  "status": 409,
  "detail": "Only 2 items of product 42 are available",
  "instance": "/api/orders",
  "code": "INSUFFICIENT_STOCK",
  "timestamp": "2026-10-15T10:15:30Z"
}
```
```yaml
spring.mvc.problemdetails.enabled: true
```

## 3. Domain exceptions

```java
public abstract class BusinessException extends RuntimeException {
    private final String code;
    protected BusinessException(String code, String message) { super(message); this.code = code; }
    public String getCode() { return code; }
}
public class NotFoundException extends BusinessException {
    public NotFoundException(String resource, Object id) {
        super("NOT_FOUND", resource + " " + id + " not found");
    }
}
public class InsufficientStockException extends BusinessException { ... }
public class InvalidOrderStateException extends BusinessException { ... }
```

## 4. Global handler

```java
@RestControllerAdvice
public class ApiExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(ApiExceptionHandler.class);

    @ExceptionHandler(NotFoundException.class)
    ProblemDetail notFound(NotFoundException e) {
        return problem(HttpStatus.NOT_FOUND, e.getCode(), e.getMessage());
    }

    @ExceptionHandler({InsufficientStockException.class, InvalidOrderStateException.class})
    ProblemDetail conflict(BusinessException e) {
        return problem(HttpStatus.CONFLICT, e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    ProblemDetail validation(MethodArgumentNotValidException e) {
        ProblemDetail pd = problem(HttpStatus.BAD_REQUEST, "VALIDATION_FAILED", "Request validation failed");
        Map<String, String> errors = new LinkedHashMap<>();
        e.getBindingResult().getFieldErrors().forEach(fe -> errors.put(fe.getField(), fe.getDefaultMessage()));
        pd.setProperty("errors", errors);
        return pd;
    }

    @ExceptionHandler(ObjectOptimisticLockingFailureException.class)
    ProblemDetail optimisticLock() {
        return problem(HttpStatus.CONFLICT, "CONCURRENT_MODIFICATION", "The resource was changed, please retry");
    }

    @ExceptionHandler(Exception.class)
    ProblemDetail unexpected(Exception e) {
        log.error("Unexpected error", e);                 // full details in logs only
        return problem(HttpStatus.INTERNAL_SERVER_ERROR, "INTERNAL_ERROR", "Unexpected error");   // no internals to client!
    }

    private ProblemDetail problem(HttpStatus status, String code, String detail) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(status, detail);
        pd.setTitle(status.getReasonPhrase());
        pd.setProperty("code", code);
        pd.setProperty("timestamp", Instant.now());
        return pd;
    }
}
```

Validation response example:
```json
{
  "status": 400,
  "code": "VALIDATION_FAILED",
  "errors": { "email": "must be a well-formed email address", "items[0].quantity": "must be greater than 0" }
}
```

## 5. Error design rules

- Machine-readable **code** (stable, for clients) + human-readable **detail**.
- Never expose stack traces, SQL, class names.
- Log unexpected errors with the correlation id; include `requestId` in the response for support.
- Map each business exception to the right status (404/409/422).
- Document error codes in OpenAPI (lesson 6).
