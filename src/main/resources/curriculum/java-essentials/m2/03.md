> **Goal:** use `static` and `final` correctly and organize code into packages.
> **Duration:** 90 min

## 1. Instance vs static

- **Instance** members belong to each object (`balance` of *this* account).
- **Static** members belong to the **class** itself (shared by all objects).

```java
public class BankAccount {
    private static int accountsCreated = 0;      // shared counter
    private static final String BANK_CODE = "NABZ";

    private final String iban;

    public BankAccount() {
        accountsCreated++;
        this.iban = "AZ00" + BANK_CODE + String.format("%020d", accountsCreated);
    }

    public static int getAccountsCreated() {
        return accountsCreated;
    }
}

new BankAccount();
new BankAccount();
System.out.println(BankAccount.getAccountsCreated());  // 2  (called on the class)
```

Rules:
- A static method **cannot** use instance fields or `this` (there is no object).
- Call static members via the class name: `Math.max(...)`, `BankAccount.getAccountsCreated()`.

## 2. When to use static

✅ Utility functions with no state: `Math.sqrt`, `Integer.parseInt`, your own `StringUtils.capitalize`.
✅ Constants: `public static final double VAT = 0.18;`
✅ `main` method.
❌ Not for data that belongs to an object. Overusing static = procedural code in disguise.

## 3. `final` everywhere

| Where | Meaning |
|---|---|
| `final` variable | cannot be reassigned |
| `final` field | must be set once (in declaration or constructor) |
| `final` method | cannot be overridden (inheritance, next lesson) |
| `final` class | cannot be extended (e.g. `String`) |

```java
final List<String> names = new ArrayList<>();
names.add("Anar");          // ✅ allowed: the object can change
// names = new ArrayList<>(); // ❌ reference cannot change
```

## 4. Packages

Packages group related classes, like folders, and avoid name conflicts.

```
src/
└── az/academy/bank/
    ├── Main.java
    ├── model/
    │   ├── BankAccount.java
    │   └── Customer.java
    ├── service/
    │   └── TransferService.java
    └── util/
        └── MoneyUtils.java
```

```java
package az.academy.bank.model;      // first line of the file

public class Customer { ... }
```
```java
package az.academy.bank;

import az.academy.bank.model.Customer;
import az.academy.bank.util.MoneyUtils;
import java.util.*;                 // wildcard import (avoid in big projects)

public class Main { ... }
```

Naming: reversed domain, lowercase: `az.kapitalbank.payments`, `com.google.common`.

## 5. Step by step: a utility class

```java
package az.academy.bank.util;

public final class MoneyUtils {

    private MoneyUtils() { }        // no objects of a utility class

    public static final String CURRENCY = "AZN";

    public static double round2(double value) {
        return Math.round(value * 100) / 100.0;
    }

    public static String format(double amount) {
        return String.format("%,.2f %s", amount, CURRENCY);
    }
}
```
```java
System.out.println(MoneyUtils.format(1234567.891));   // 1,234,567.89 AZN
```

## 6. Static imports (use carefully)

```java
import static java.lang.Math.*;
double r = sqrt(pow(3, 2) + pow(4, 2));
```

## 7. Common mistakes

- ❌ "Non-static variable cannot be referenced from a static context": you used an instance field in `main`. Create an object first.
- ❌ Mutable `static` fields used as global variables.
- ❌ Package declaration not matching the folder.

2. What is the purpose of a private constructor in a utility class?
3. A `final` list: can we add elements?

<details><summary>Answers</summary>

1. Static methods belong to the class; there is no current object.
2. To prevent creating instances: the class only has static members.
3. Yes: `final` fixes the reference, not the object's content.
