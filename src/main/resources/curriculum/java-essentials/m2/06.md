> **Goal:** design with interfaces and prefer composition over inheritance.
> **Duration:** 90 min

## 1. What is an interface?

An interface is a **contract**: "anything that implements me can do these things". It says **what**, not **how**.

```java
public interface Payable {
    double amountDue();
    void pay(double amount);
}
```
```java
public class Invoice implements Payable {
    private double total;
    private double paid;

    public Invoice(double total) { this.total = total; }

    @Override public double amountDue() { return total - paid; }
    @Override public void pay(double amount) { paid += amount; }
}

public class UtilityBill implements Payable {
    ...
}
```
```java
Payable[] toPay = { new Invoice(500), new UtilityBill("Azersu", 23.4) };
for (Payable p : toPay) {
    p.pay(p.amountDue());
}
```

## 2. Interface vs abstract class

| | Interface | Abstract class |
|---|---|---|
| Multiple | a class can implement **many** | extend only **one** |
| Fields | only constants (`static final`) | any fields |
| Constructors | no | yes |
| Purpose | capability / contract ("can do") | shared base ("is a") |

A class can do both: `class Manager extends Employee implements Payable, Comparable<Manager>`.

## 3. Default and static methods

```java
public interface Notifier {
    void send(String to, String message);

    default void sendAll(String[] recipients, String message) {   // shared implementation
        for (String r : recipients) send(r, message);
    }

    static Notifier console() {                                    // factory
        return (to, msg) -> System.out.println("To " + to + ": " + msg);
    }
}
```

## 4. Programming to an interface

```java
public class OrderService {
    private final Notifier notifier;          // depends on the INTERFACE

    public OrderService(Notifier notifier) {  // the concrete class is given from outside
        this.notifier = notifier;
    }

    public void placeOrder(String customerPhone) {
        // ... save order
        notifier.send(customerPhone, "Your order is confirmed");
    }
}

new OrderService(new SmsNotifier());
new OrderService(new EmailNotifier());
new OrderService(Notifier.console());        // for testing
```
This idea, **dependency injection**, is the heart of Spring (Java Advanced, month 4).

## 5. Composition over inheritance

Inheritance = **is-a**. Composition = **has-a** (a field).

```java
// ❌ Car extends Engine
// ✅
public class Car {
    private final Engine engine;
    private final GpsNavigator gps;

    public Car(Engine engine, GpsNavigator gps) {
        this.engine = engine;
        this.gps = gps;
    }

    public void start() {
        engine.start();
    }
}
```
Composition is more flexible: you can swap an `ElectricEngine` for a `PetrolEngine` without changing `Car`.

## 6. Functional interfaces (preview)

An interface with exactly **one** abstract method can be implemented with a lambda:
```java
@FunctionalInterface
public interface DiscountPolicy {
    double apply(double price);
}

DiscountPolicy noDiscount = price -> price;
DiscountPolicy blackFriday = price -> price * 0.7;
```
We go deep into this in month 4.

## 7. Common mistakes

- ❌ Huge interfaces with 20 methods. Keep them small and focused (Interface Segregation).
- ❌ Depending on concrete classes everywhere (`SmsNotifier sms = new SmsNotifier()` inside services).
- ❌ Using inheritance for has-a relationships.
