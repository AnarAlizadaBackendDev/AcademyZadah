> **Goal:** use records, enums and wrapper classes in everyday code.
> **Duration:** 90 min

## 1. Records (Java 16+)

Many classes only carry data. Writing fields, constructor, getters, `equals`, `hashCode`, `toString` is boring. A **record** generates all of it:

```java
public record Transaction(String id, double amount, String currency) { }

Transaction t = new Transaction("TX1", 49.99, "AZN");
t.amount();                // accessor (no "get" prefix)
System.out.println(t);     // Transaction[id=TX1, amount=49.99, currency=AZN]
t.equals(new Transaction("TX1", 49.99, "AZN"));   // true
```

Records are **immutable**. You can add validation and methods:
```java
public record Money(double amount, String currency) {
    public Money {                                  // compact constructor
        if (amount < 0) throw new IllegalArgumentException("Negative amount");
        if (currency == null) throw new IllegalArgumentException("Currency required");
    }

    public Money add(Money other) {
        return new Money(amount + other.amount, currency);
    }
}
```
Use records for DTOs, values, results. Don't use them for entities whose state changes.

## 2. Enums

An enum is a fixed set of constants.
```java
public enum OrderStatus {
    NEW, PAID, SHIPPED, DELIVERED, CANCELLED
}

OrderStatus status = OrderStatus.NEW;
if (status == OrderStatus.NEW) { ... }        // == is fine for enums
OrderStatus.valueOf("PAID");                  // String → enum
OrderStatus.values();                         // all constants
status.name();                                // "NEW"
```

### Enums with fields and methods
```java
public enum CardType {
    DEBIT(0.0), CREDIT(0.02), PREMIUM(0.01);

    private final double feeRate;

    CardType(double feeRate) { this.feeRate = feeRate; }

    public double fee(double amount) { return amount * feeRate; }
}

CardType.CREDIT.fee(1000);   // 20.0
```

### Enums with switch
```java
String label = switch (status) {
    case NEW -> "Waiting for payment";
    case PAID, SHIPPED -> "In progress";
    case DELIVERED -> "Done";
    case CANCELLED -> "Cancelled";
};                                      // no default needed: all cases covered
```

## 3. Wrapper classes

Each primitive has a class version:

| Primitive | Wrapper |
|---|---|
| `int` | `Integer` |
| `long` | `Long` |
| `double` | `Double` |
| `boolean` | `Boolean` |
| `char` | `Character` |

Why? Collections (`List<Integer>`) work only with objects, and wrappers can be `null`.

### Autoboxing / unboxing
```java
Integer boxed = 42;          // autoboxing
int raw = boxed;             // unboxing
Integer nothing = null;
// int x = nothing;          // ❌ NullPointerException!
```

### Useful methods
```java
Integer.parseInt("123")
Double.parseDouble("19.99")
Integer.MAX_VALUE
Character.isDigit('5')
Character.isLetter('a')
```

### Comparing wrappers
```java
Integer a = 1000, b = 1000;
System.out.println(a == b);       // false! (different objects)
System.out.println(a.equals(b));  // true ✅
```
(Values -128..127 are cached, so `==` *sometimes* works: a classic interview trap.)

## 4. Step by step: an order model

```java
public enum OrderStatus { NEW, PAID, SHIPPED, DELIVERED, CANCELLED }

public record OrderItem(String product, int quantity, double unitPrice) {
    public double total() { return quantity * unitPrice; }
}

public class Order {
    private final OrderItem[] items;
    private OrderStatus status = OrderStatus.NEW;

    public Order(OrderItem... items) { this.items = items; }

    public double total() {
        double sum = 0;
        for (OrderItem i : items) sum += i.total();
        return sum;
    }

    public void pay() {
        if (status != OrderStatus.NEW) throw new IllegalStateException("Order is " + status);
        status = OrderStatus.PAID;
    }

    public OrderStatus getStatus() { return status; }
}
```
(`OrderItem... items` is **varargs**: any number of arguments.)

## 5. Common mistakes

- ❌ Strings like `"PAID"` instead of enums: typos compile fine and fail later.
- ❌ `==` for `Integer`/`Double`.
- ❌ Unboxing `null`.
- ❌ Records for mutable entities.

Extend the order model: `Order.ship()`, `deliver()`, `cancel()` with valid transitions only (e.g. cannot ship a NEW order, cannot cancel a delivered one). Print the order history.

## 8. Self-check

1. What does a record generate automatically?
2. Why are enums better than String constants?
3. Why is `Integer a = 1000, b = 1000; a == b` false?

<details><summary>Answers</summary>

1. Private final fields, constructor, accessors, equals, hashCode, toString.
2. Type safety: only valid values compile; IDE autocompletion; switch exhaustiveness.
3. They are two different objects; `==` compares references (only -128..127 are cached).

</details>
