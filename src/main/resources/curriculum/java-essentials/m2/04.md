> **Goal:** reuse and extend behaviour with inheritance and understand the `Object` class.
> **Duration:** 90 min

## 1. The idea

A **Manager** *is an* **Employee**. A **SavingsAccount** *is a* **BankAccount**. Inheritance lets a subclass reuse the fields and methods of a superclass and add or change behaviour.

```java
public class Employee {
    protected final String name;
    protected final double baseSalary;

    public Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public double monthlySalary() {
        return baseSalary;
    }

    public String getName() { return name; }
}

public class Manager extends Employee {
    private final double bonus;

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);          // call parent constructor FIRST
        this.bonus = bonus;
    }

    @Override
    public double monthlySalary() {
        return super.monthlySalary() + bonus;
    }
}
```

## 2. Key rules

- `extends`: Java supports only **single** class inheritance.
- `super(...)`: calls the parent constructor; must be the first line.
- `super.method()`: calls the parent's version of a method.
- `protected`: accessible in subclasses.
- Private members are **not** accessible in subclasses (use getters).

## 3. Overriding vs overloading

| | Overriding | Overloading |
|---|---|---|
| Where | subclass | same class |
| Signature | **same** | different parameters |
| Decided at | runtime | compile time |

Always use `@Override`: the compiler checks that you really override something.

```java
@Override
public double monthlySalry() { ... }   // typo → compile error thanks to @Override
```

## 4. The `Object` class

Every class extends `java.lang.Object` automatically. Important methods:

### `toString()`
```java
@Override
public String toString() {
    return getClass().getSimpleName() + "{name='" + name + "'}";
}
```

### `equals()` and `hashCode()`
By default `equals` compares references (like `==`). For value objects we override it:
```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Employee other)) return false;
    return name.equals(other.name) && baseSalary == other.baseSalary;
}

@Override
public int hashCode() {
    return java.util.Objects.hash(name, baseSalary);
}
```
**Contract:** if `a.equals(b)` then `a.hashCode() == b.hashCode()`. Always override both together (critical for `HashMap`/`HashSet` in month 3). IntelliJ: Alt+Insert → equals() and hashCode().

## 5. Constructor chaining order

```java
new Manager("Aysel", 3000, 800);
// 1. Object constructor
// 2. Employee constructor
// 3. Manager constructor
```

## 6. When NOT to use inheritance

Use inheritance only for a real **is-a** relationship. ❌ `class Car extends Engine`: a car *has an* engine → use a field (composition, lesson 6).

## 7. Step by step: account hierarchy

```java
public class SavingsAccount extends BankAccount {
    private final double interestRate;

    public SavingsAccount(String owner, String iban, double interestRate) {
        super(owner, iban);
        this.interestRate = interestRate;
    }

    public void addMonthlyInterest() {
        deposit(getBalance() * interestRate / 12);
    }

    @Override
    public boolean withdraw(double amount) {
        if (amount > 1000) {                // savings: limited withdrawals
            return false;
        }
        return super.withdraw(amount);
    }
}
```

## 8. Common mistakes

- ❌ Forgetting `super(...)` when the parent has no default constructor → compile error.
- ❌ Overriding `equals` without `hashCode`.
- ❌ Deep hierarchies (5+ levels): hard to understand.
- ❌ Using inheritance just to reuse code.

## 11. Self-check

1. What does `super(...)` do and where must it be?
2. Difference between overriding and overloading?
3. Why must `hashCode` be overridden together with `equals`?

<details><summary>Answers</summary>

1. Calls the parent constructor; it must be the first statement of the constructor.
2. Overriding = same signature in subclass (runtime); overloading = same name, different params (compile time).
3. Hash-based collections use `hashCode` first; equal objects with different hash codes would break `HashMap`/`HashSet`.

</details>
