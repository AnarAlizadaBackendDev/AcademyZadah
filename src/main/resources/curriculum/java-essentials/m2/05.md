> **Goal:** write flexible code with polymorphism and abstract classes.
> **Duration:** 90 min

## 1. Polymorphism = "many forms"

A variable of a parent type can hold any subclass object, and the **actual object's** method runs.

```java
Employee e1 = new Manager("Aysel", 3000, 800);
Employee e2 = new Employee("Orxan", 1500);

System.out.println(e1.monthlySalary());   // 3800 → Manager's version
System.out.println(e2.monthlySalary());   // 1500
```
This is called **dynamic dispatch**: the JVM chooses the method at runtime based on the real object.

## 2. Why it matters

```java
Employee[] staff = {
    new Employee("Orxan", 1500),
    new Manager("Aysel", 3000, 800),
    new Developer("Kamran", 2500, "SENIOR")
};

double total = 0;
for (Employee e : staff) {
    total += e.monthlySalary();     // no if/else for types!
}
```
Adding a new type (e.g. `Contractor`) requires **no change** in this loop. This is the **Open/Closed principle**: open for extension, closed for modification.

## 3. Upcasting and downcasting

```java
Employee e = new Manager("Aysel", 3000, 800);   // upcasting (automatic)
// e.getBonus();                                 // ❌ Employee has no getBonus

if (e instanceof Manager m) {                    // pattern matching (Java 16+)
    System.out.println(m.getBonus());            // ✅ safe downcast
}
```
Wrong downcast → `ClassCastException`. Frequent `instanceof` usually signals bad design.

## 4. Abstract classes

Some classes should never be instantiated: there is no "generic shape", only circles, rectangles...

```java
public abstract class Shape {
    private final String color;

    protected Shape(String color) {
        this.color = color;
    }

    public abstract double area();          // no body: subclasses MUST implement

    public String describe() {              // normal method shared by all
        return color + " " + getClass().getSimpleName() + " with area " + String.format("%.2f", area());
    }
}

public class Circle extends Shape {
    private final double radius;
    public Circle(String color, double radius) { super(color); this.radius = radius; }
    @Override public double area() { return Math.PI * radius * radius; }
}

public class Rectangle extends Shape {
    private final double width, height;
    public Rectangle(String color, double w, double h) { super(color); width = w; height = h; }
    @Override public double area() { return width * height; }
}
```
```java
// new Shape("red");   ❌ cannot instantiate
Shape[] shapes = { new Circle("red", 2), new Rectangle("blue", 3, 4) };
for (Shape s : shapes) System.out.println(s.describe());
```

- An abstract class can have fields, constructors and normal methods.
- A class with at least one abstract method must be abstract.
- A subclass must implement all abstract methods (or be abstract itself).

## 5. Template Method pattern

```java
public abstract class PaymentProcessor {
    public final void process(double amount) {   // the fixed algorithm
        validate(amount);
        charge(amount);
        sendReceipt(amount);
    }
    private void validate(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Invalid amount");
    }
    protected abstract void charge(double amount);    // steps that vary
    protected void sendReceipt(double amount) {
        System.out.println("Receipt: " + amount);
    }
}

public class CardPayment extends PaymentProcessor {
    @Override protected void charge(double amount) { System.out.println("Charging card " + amount); }
}
public class QrPayment extends PaymentProcessor {
    @Override protected void charge(double amount) { System.out.println("QR payment " + amount); }
}
```

## 6. Common mistakes

- ❌ Long `if (x instanceof A) ... else if (x instanceof B)` chains instead of an overridden method.
- ❌ Trying to create an abstract class with `new`.
- ❌ Calling a subclass-only method on a parent-type variable without a check.

2. Can an abstract class have a constructor? Why?
3. How do you safely call a `Manager`-only method on an `Employee` variable?
