> **Goal:** write type-safe, reusable code with generics.
> **Duration:** 90 min

## 1. The problem without generics

```java
Object[] box = new Object[10];
box[0] = "hello";
box[1] = 42;
String s = (String) box[1];   // compiles, crashes at runtime: ClassCastException
```
Generics move these errors to **compile time**.

## 2. A generic class

```java
public class Box<T> {
    private T value;

    public void put(T value) { this.value = value; }
    public T get() { return value; }
    public boolean isEmpty() { return value == null; }
}

Box<String> name = new Box<>();     // diamond operator <>
name.put("Anar");
String s = name.get();              // no cast needed
// name.put(42);                    // ❌ compile error
```
`T` is a **type parameter**. Conventions: `T` type, `E` element, `K` key, `V` value, `R` result.

## 3. Multiple type parameters

```java
public record Pair<K, V>(K key, V value) { }

Pair<String, Integer> score = new Pair<>("Leyla", 95);
```

## 4. Generic methods

```java
public static <T> T firstOrDefault(T[] array, T defaultValue) {
    return array.length > 0 ? array[0] : defaultValue;
}

String s = firstOrDefault(new String[]{}, "none");
```

## 5. Bounded types

Restrict `T` to certain types:
```java
public static <T extends Comparable<T>> T max(T[] items) {
    T best = items[0];
    for (T item : items) {
        if (item.compareTo(best) > 0) best = item;
    }
    return best;
}

max(new Integer[]{3, 9, 4});           // 9
max(new String[]{"kiwi", "apple"});    // "kiwi"
```

```java
public static double sum(List<? extends Number> numbers) {   // Integer, Double, Long...
    double total = 0;
    for (Number n : numbers) total += n.doubleValue();
    return total;
}
```

## 6. Wildcards: PECS

| Wildcard | Meaning | Use when |
|---|---|---|
| `List<?>` | any type | only reading as `Object` |
| `List<? extends Number>` | Number or subtype | you **read** (Producer **E**xtends) |
| `List<? super Integer>` | Integer or supertype | you **write** (Consumer **S**uper) |

```java
static void addNumbers(List<? super Integer> target) {
    target.add(1);
    target.add(2);
}
```

## 7. Generics and primitives

Type parameters work only with objects: `Box<int>` ❌ → `Box<Integer>` ✅ (autoboxing).

## 8. Step by step: a generic Result type

```java
public sealed interface Result<T> permits Result.Ok, Result.Error {
    record Ok<T>(T value) implements Result<T> { }
    record Error<T>(String message) implements Result<T> { }
}

static Result<Integer> parse(String s) {
    try {
        return new Result.Ok<>(Integer.parseInt(s));
    } catch (NumberFormatException e) {
        return new Result.Error<>("Not a number: " + s);
    }
}
```
(We will see `sealed` in Advanced; the important part here is `Result<T>`.)

## 9. Common mistakes

- ❌ Raw types: `List list = new ArrayList();` (no type, no safety). Always specify `<T>`.
- ❌ `new T()` or `new T[10]`: not allowed (type erasure).
- ❌ Overusing generics where a simple class is enough.

## 10. Exercises

1. Generic `Pair<A, B>` with a `swap()` method returning `Pair<B, A>`.
2. Generic method `count(T[] array, T value)`.
3. Generic `Cache<K, V>` backed by two arrays with `put`, `get`, `size`.

## 11. Homework

Write a generic `Repository<T, ID>` interface with `save`, `findById`, `findAll`, `delete`, and an array-based implementation `InMemoryRepository<T extends Identifiable<ID>, ID>`. Use it for both `Book` and `Member`.

## 12. Self-check

1. What problem do generics solve?
2. What does `<T extends Comparable<T>>` mean?
3. Why can't we write `List<int>`?

<details><summary>Answers</summary>

1. Type safety at compile time and reuse without casts.
2. T must be a type that can compare itself to another T.
3. Generics work only with reference types; use `Integer`.

</details>
