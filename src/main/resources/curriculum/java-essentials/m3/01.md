> **Goal:** handle errors gracefully with exceptions.
> **Duration:** 90 min

## 1. What is an exception?

An exception is an **event that interrupts** the normal flow of a program: invalid input, missing file, division by zero, network failure.

```java
int[] a = new int[3];
a[5] = 1;            // ArrayIndexOutOfBoundsException
String s = null;
s.length();          // NullPointerException
Integer.parseInt("abc");  // NumberFormatException
```
Without handling, the program **crashes** and prints a **stack trace**.

## 2. Reading a stack trace

```
Exception in thread "main" java.lang.NumberFormatException: For input string: "abc"
    at java.base/java.lang.Integer.parseInt(Integer.java:661)
    at az.academy.App.readAge(App.java:14)
    at az.academy.App.main(App.java:7)
```
Read it top-down: **type + message**, then find the first line from **your code** (`App.java:14`).

## 3. try / catch / finally

```java
try {
    int age = Integer.parseInt(input);
    System.out.println("Age: " + age);
} catch (NumberFormatException e) {
    System.out.println("Please enter a number, not: " + input);
} finally {
    System.out.println("Always runs (cleanup)");
}
```

Multiple catches (most specific first):
```java
try {
    ...
} catch (FileNotFoundException e) {
    ...
} catch (IOException e) {
    ...
}

// or multi-catch
catch (NumberFormatException | ArithmeticException e) { ... }
```

## 4. The exception hierarchy

```
Throwable
├── Error                       (JVM problems: OutOfMemoryError; don't catch)
└── Exception
    ├── IOException, SQLException...   → CHECKED
    └── RuntimeException                → UNCHECKED
        ├── NullPointerException
        ├── IllegalArgumentException
        ├── IllegalStateException
        └── IndexOutOfBoundsException
```

| | Checked | Unchecked |
|---|---|---|
| Extends | `Exception` | `RuntimeException` |
| Compiler forces handling? | **yes** (catch or `throws`) | no |
| Typical cause | outside world (file, network) | programming bug / invalid argument |

## 5. `throws` and `throw`

```java
public String readConfig(Path path) throws IOException {   // declares: caller must handle
    return Files.readString(path);
}

public void withdraw(double amount) {
    if (amount <= 0) {
        throw new IllegalArgumentException("Amount must be positive: " + amount);   // throw an exception
    }
}
```

## 6. try-with-resources

Resources (files, DB connections, Scanner) must be closed. This syntax closes them automatically, even if an exception happens:
```java
try (BufferedReader reader = Files.newBufferedReader(Path.of("data.txt"))) {
    System.out.println(reader.readLine());
} catch (IOException e) {
    System.out.println("Cannot read file: " + e.getMessage());
}
```
Works with any class implementing `AutoCloseable`.

## 7. Step by step: safe number input

```java
static int readInt(Scanner in, String prompt, int min, int max) {
    while (true) {
        System.out.print(prompt);
        String line = in.nextLine();
        try {
            int value = Integer.parseInt(line.trim());
            if (value < min || value > max) {
                System.out.printf("Enter a number between %d and %d%n", min, max);
                continue;
            }
            return value;
        } catch (NumberFormatException e) {
            System.out.println("'" + line + "' is not a number");
        }
    }
}
```

## 8. Common mistakes

- ❌ Empty catch block `catch (Exception e) { }`: errors disappear silently.
- ❌ Catching `Exception` everywhere instead of specific types.
- ❌ Using exceptions for normal flow control (e.g. to exit a loop).
- ❌ Forgetting to close resources.

## 11. Self-check

1. Difference between checked and unchecked exceptions?
2. When does `finally` run?
3. Why use try-with-resources?

<details><summary>Answers</summary>

1. Checked must be caught or declared (compiler-enforced); unchecked (RuntimeException) are not.
2. Always: after try or catch, even if an exception was thrown or `return` was called.
3. It closes resources automatically and safely, even when exceptions occur.

</details>
