> **Goal:** store dynamic collections of data with `List` and understand complexity basics.
> **Duration:** 90 min

## 1. Why collections?

Arrays have a **fixed size**. Real data grows and shrinks: orders, users, transactions. The **Java Collections Framework** gives ready-made data structures.

```
Iterable
└── Collection
    ├── List   (ordered, duplicates allowed)   → ArrayList, LinkedList
    ├── Set    (no duplicates)                 → HashSet, LinkedHashSet, TreeSet
    └── Queue  (processing order)              → ArrayDeque, PriorityQueue
Map (key → value)                              → HashMap, LinkedHashMap, TreeMap
```

## 2. ArrayList

```java
import java.util.ArrayList;
import java.util.List;

List<String> cities = new ArrayList<>();    // declare with the interface!
cities.add("Baku");
cities.add("Ganja");
cities.add(0, "Shusha");                     // insert at index
cities.get(1);                               // "Baku"
cities.set(1, "Sumgait");
cities.remove("Ganja");
cities.remove(0);
cities.size();
cities.contains("Baku");
cities.indexOf("Baku");
cities.isEmpty();
cities.clear();
```

Creating with values:
```java
List<Integer> fixed = List.of(1, 2, 3);           // immutable!
List<Integer> mutable = new ArrayList<>(List.of(1, 2, 3));
```

## 3. Iterating

```java
for (String c : cities) System.out.println(c);

for (int i = 0; i < cities.size(); i++) System.out.println(i + ": " + cities.get(i));

cities.forEach(c -> System.out.println(c));   // lambda (month 4)
```

### Removing while iterating
```java
for (String c : cities) {
    if (c.startsWith("G")) cities.remove(c);   // ❌ ConcurrentModificationException
}
cities.removeIf(c -> c.startsWith("G"));       // ✅
```

## 4. ArrayList vs LinkedList

| Operation | ArrayList | LinkedList |
|---|---|---|
| `get(i)` | **O(1)** fast | O(n) slow |
| add at end | O(1)* | O(1) |
| add/remove in the middle | O(n) | O(1) once you're there |
| memory | compact | extra pointers |

*amortized. **In practice use `ArrayList` almost always.**

## 5. Big-O in 2 minutes

How the time grows when data grows (n = number of elements):

| Big-O | Name | Example |
|---|---|---|
| O(1) | constant | `list.get(5)`, `map.get(key)` |
| O(log n) | logarithmic | binary search, `TreeMap.get` |
| O(n) | linear | `list.contains(x)`, one loop |
| O(n log n) | | sorting |
| O(n²) | quadratic | nested loops over the same list |

With 1,000,000 elements: O(n) ≈ 1M steps, O(n²) ≈ 1,000,000,000,000 steps. That's why it matters.

## 7. Step by step: a to-do manager

```java
public record Task(int id, String title, boolean done) {
    Task complete() { return new Task(id, title, true); }
}

public class TodoList {
    private final List<Task> tasks = new ArrayList<>();
    private int nextId = 1;

    public Task add(String title) {
        Task t = new Task(nextId++, title, false);
        tasks.add(t);
        return t;
    }

    public void complete(int id) {
        for (int i = 0; i < tasks.size(); i++) {
            if (tasks.get(i).id() == id) {
                tasks.set(i, tasks.get(i).complete());
                return;
            }
        }
        throw new IllegalArgumentException("No task " + id);
    }

    public List<Task> pending() {
        List<Task> result = new ArrayList<>();
        for (Task t : tasks) if (!t.done()) result.add(t);
        return result;
    }

    public List<Task> all() {
        return List.copyOf(tasks);         // don't expose the internal list
    }
}
```

## 8. Common mistakes

- ❌ `ArrayList<String> list = new ArrayList<>()` everywhere: prefer `List<String>`.
- ❌ Modifying a list while iterating with for-each.
- ❌ `list.remove(1)` on `List<Integer>` removes index 1, not the value 1. Use `list.remove(Integer.valueOf(1))`.
- ❌ Calling `add` on `List.of(...)` → `UnsupportedOperationException`.

## 11. Self-check

1. Why declare `List<String> x = new ArrayList<>()` and not `ArrayList<String>`?
2. What is the complexity of `contains` in an ArrayList?
3. How do you safely remove elements while iterating?

<details><summary>Answers</summary>

1. Programming to an interface: you can change the implementation without changing the rest of the code.
2. O(n): it checks elements one by one.
3. `removeIf(...)` or an explicit `Iterator` with `iterator.remove()`.

</details>
