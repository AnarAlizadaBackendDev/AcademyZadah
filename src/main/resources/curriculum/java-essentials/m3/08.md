> **Goal:** version your code with Git and GitHub, and build the Month 3 mini project.
> **Duration:** 90 min + project week

## 1. Why Git?

- History of every change ("what changed yesterday?").
- Safe experiments with branches.
- Teamwork: every company uses Git. Your GitHub is your **portfolio**.

## 2. Setup

```bash
git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```
Create an account on github.com.

## 3. Core workflow

```bash
git init                       # start a repository
git status                     # what changed?
git add .                      # stage changes
git commit -m "Add Book and Member classes"
git log --oneline              # history
```

```
working directory --git add--> staging area --git commit--> repository
```

### `.gitignore`
```
out/
build/
target/
.idea/
*.class
```

## 4. Branches

```bash
git switch -c feature/search      # create & switch
# ... work, commit ...
git switch main
git merge feature/search
git branch -d feature/search
```

## 5. GitHub

```bash
git remote add origin https://github.com/<you>/library-app.git
git branch -M main
git push -u origin main
git pull                          # get others' changes
git clone <url>                   # copy a repository
```

### Pull requests (team workflow)
1. Create a branch, commit, push.
2. Open a **Pull Request** on GitHub.
3. Teammates review and comment.
4. Merge into `main`.

## 6. Good commit messages

✅ `Add overdue fine calculation`
✅ `Fix NPE when member has no loans`
❌ `update`, `fix`, `asdf`

One commit = one logical change.

## 7. A good README

```markdown
# Contact Book
Console app to manage contacts (Java 21).

## Features
- Add, edit, delete contacts
- Search by name or phone
- Sort by name / date added

## Run
javac -d out src/**/*.java && java -cp out app.Main
```

## 8. Resolving a merge conflict

```
<<<<<<< HEAD
System.out.println("Hello");
=======
System.out.println("Salam");
>>>>>>> feature/greeting
```
Choose the right version, delete the markers, `git add`, `git commit`. IntelliJ has a visual merge tool.

## 9. 🏁 Month 3 Project: Contact Book

### Requirements
1. `Contact` (id, name, phone, email, tags, createdAt). Phone and email validated with regex.
2. Store contacts in a `Map<Integer, Contact>`; tags in a `Set<String>`.
3. Features:
   - add / edit / delete
   - search by name (partial, case-insensitive) or phone
   - list sorted by name or by creation date (`Comparator`)
   - filter by tag
   - show duplicates (same phone)
4. Custom exceptions: `ContactNotFoundException`, `InvalidContactException`; menu never crashes.
5. Code on **GitHub** with ≥ 8 meaningful commits, a README and `.gitignore`.

### Evaluation checklist
- [ ] Correct use of List / Set / Map
- [ ] Comparators for sorting
- [ ] Validation and custom exceptions
- [ ] Clean packages and small methods
- [ ] GitHub repository with good commits and README

## 10. Self-check

1. What is the staging area?
2. Why use branches?
3. What should never be committed?

<details><summary>Answers</summary>

1. The place where you prepare (stage) changes before committing them.
2. To develop features/fixes in isolation without breaking main.
3. Build output, IDE files, secrets (passwords, tokens), large binaries.

</details>
