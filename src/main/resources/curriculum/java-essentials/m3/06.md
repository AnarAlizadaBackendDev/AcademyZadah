> **Goal:** use queues and deques, and sort anything with `Comparable` and `Comparator`.
> **Duration:** 90 min

## 1. Queue: first in, first out (FIFO)

```java
Queue<String> customers = new ArrayDeque<>();
customers.offer("Leyla");     // add to the end
customers.offer("Murad");
customers.peek();             // "Leyla" (look, don't remove)
customers.poll();             // "Leyla" (remove from the front)
customers.size();             // 1
```

## 2. Deque: both ends (also a stack, LIFO)

```java
Deque<String> history = new ArrayDeque<>();
history.push("page1");     // stack push
history.push("page2");
history.pop();             // "page2" (last in, first out)
history.offerFirst("x");
history.offerLast("y");
```
Use `ArrayDeque` instead of the old `Stack` class.

## 3. PriorityQueue: the smallest (or highest priority) first

```java
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.addAll(List.of(5, 1, 8, 3));
pq.poll();   // 1
pq.poll();   // 3
```

## 4. Comparable: the natural order

```java
public record Product(String name, double price) implements Comparable<Product> {
    @Override
    public int compareTo(Product other) {
        return Double.compare(this.price, other.price);   // negative / 0 / positive
    }
}

List<Product> products = new ArrayList<>(...);
Collections.sort(products);     // by price
```

`compareTo` returns:
- **negative** if this < other
- **0** if equal
- **positive** if this > other

## 5. Comparator: any order you want

```java
Comparator<Product> byName = Comparator.comparing(Product::name);
Comparator<Product> byPriceDesc = Comparator.comparingDouble(Product::price).reversed();

products.sort(byName);
products.sort(byPriceDesc);

// chaining: by category, then price, then name
products.sort(Comparator.comparing(Product::category)
        .thenComparing(Product::price)
        .thenComparing(Product::name));

// nulls safely
Comparator.comparing(Employee::department, Comparator.nullsLast(Comparator.naturalOrder()));
```

## 6. Step by step: bank queue simulation

```java
record Client(String name, boolean vip, int arrivalOrder) { }

PriorityQueue<Client> queue = new PriorityQueue<>(
        Comparator.comparing(Client::vip).reversed()        // VIP first
                  .thenComparingInt(Client::arrivalOrder));  // then by arrival

queue.add(new Client("Leyla", false, 1));
queue.add(new Client("Murad", true, 2));
queue.add(new Client("Aysel", false, 3));

while (!queue.isEmpty()) {
    System.out.println("Serving " + queue.poll().name());   // Murad, Leyla, Aysel
}
```

## 7. Which collection? (final table)

| Situation | Use |
|---|---|
| process in arrival order | `ArrayDeque` as Queue |
| undo/back history | `ArrayDeque` as stack |
| always take the most urgent | `PriorityQueue` |
| sort a list once | `list.sort(comparator)` |
| always keep sorted | `TreeSet` / `TreeMap` with comparator |

## 8. Common mistakes

- ❌ `return this.price - other.price` in compareTo with doubles (precision) or big ints (overflow). Use `Double.compare` / `Integer.compare`.
- ❌ Inconsistent compareTo and equals inside a TreeSet (elements "disappear").
- ❌ Iterating a PriorityQueue expecting sorted order (only `poll()` gives order).

3. What does `compareTo` return when objects are equal?

1. Queue: FIFO; stack: LIFO.
2. When you need an order different from the natural one, or several orders, or can't modify the class.
