> **Goal:** split programs into reusable methods with parameters and return values.
> **Duration:** 90 min

## 1. Why methods?

- **Reuse**: write once, call many times.
- **Readability**: `calculateLoanPayment(...)` explains itself.
- **Testing**: small methods are easy to test (month 4).
- **DRY**: Don't Repeat Yourself.

## 2. Anatomy of a method

```java
public static double calculateVat(double amount, double rate) {
    double vat = amount * rate;
    return vat;
}
```

| Part | Meaning |
|---|---|
| `public static` | for now: required to call it from `main` (explained in month 2) |
| `double` | return type (`void` = returns nothing) |
| `calculateVat` | name: a verb, camelCase |
| `(double amount, double rate)` | parameters |
| `return vat;` | sends the result back and ends the method |

Calling it:
```java
double vat = calculateVat(100, 0.18);   // arguments: 100, 0.18
```

## 3. `void` methods

```java
static void printSeparator(int length) {
    System.out.println("-".repeat(length));
}
```

## 4. Overloading

Same name, different parameter lists:
```java
static int sum(int a, int b) { return a + b; }
static double sum(double a, double b) { return a + b; }
static int sum(int a, int b, int c) { return a + b + c; }
```
The compiler picks the right one by the argument types. A different **return type alone** is not enough.

## 5. Scope

A variable exists only inside the block `{ }` where it was declared.
```java
static void demo() {
    int x = 5;
    if (x > 0) {
        int y = 10;     // only inside the if
    }
    // System.out.println(y);   // ❌ compile error
}
```
Variables from `main` are **not** visible in other methods: pass them as parameters.

## 6. Pass-by-value

Java always passes a **copy** of the value.
```java
static void addBonus(int salary) {
    salary += 100;            // changes the copy only
}
int salary = 1000;
addBonus(salary);
System.out.println(salary);   // 1000
```
To get a result, **return** it: `salary = addBonus(salary);`

## 7. Recursion (intro)

A method that calls itself. It needs a **base case**.
```java
static long factorial(int n) {
    if (n <= 1) return 1;          // base case
    return n * factorial(n - 1);   // recursive step
}
```
Without a base case → `StackOverflowError`.

## 8. Step by step: refactor the loan program

```java
public class LoanApp {
    public static void main(String[] args) {
        double payment = monthlyPayment(10_000, 12, 24);
        printLine();
        System.out.printf("Monthly: %.2f AZN%n", payment);
        System.out.printf("Total:   %.2f AZN%n", payment * 24);
        System.out.println("Eligible: " + isEligible(30, 1500));
        printLine();
    }

    static double monthlyPayment(double principal, double annualRatePercent, int months) {
        double r = annualRatePercent / 100 / 12;
        return principal * r / (1 - Math.pow(1 + r, -months));
    }

    static boolean isEligible(int age, double salary) {
        return age >= 21 && age <= 65 && salary >= 700;
    }

    static void printLine() {
        System.out.println("=".repeat(30));
    }
}
```

## 9. Good method rules

- One method = **one job**.
- Short: ideally fits on the screen.
- Name with a verb: `calculate`, `is`, `has`, `print`, `find`.
- Avoid more than 3–4 parameters.

## 10. Common mistakes

- ❌ Missing `return` in a non-void method (compile error).
- ❌ Code after `return` (unreachable).
- ❌ Expecting a method to change a primitive argument.
- ❌ Recursion without a base case.

## 11. Exercises

1. `isEven(int n)`, `max(int a, int b, int c)`, `isPrime(int n)`.
2. `celsiusToFahrenheit(double c)` and the reverse.
3. Overload `area`: circle (radius), rectangle (w, h).
4. Recursive `fibonacci(n)` and `sumDigits(n)`.

## 13. Self-check

1. What does `void` mean?
2. Can two methods have the same name? When?
3. Why doesn't `addBonus(salary)` change `salary` in `main`?

2. Yes, if their parameter lists differ (overloading).
