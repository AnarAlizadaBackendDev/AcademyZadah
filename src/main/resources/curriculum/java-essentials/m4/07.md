> **Goal:** build projects with Gradle/Maven and write clean, professional code.
> **Duration:** 90 min

## 1. Why build tools?

Without them you download JARs manually, compile with long commands and every developer has a different setup. Build tools:
- download **dependencies** automatically,
- compile, test and package with one command,
- give every project the **same structure**.

## 2. Standard layout

```
my-app/
├── build.gradle            (or pom.xml for Maven)
├── settings.gradle
├── gradlew / gradlew.bat   (Gradle wrapper)
└── src/
    ├── main/java/az/academy/...       production code
    ├── main/resources/                config files
    └── test/java/az/academy/...       tests
```

## 3. Gradle

```groovy
plugins {
    id 'application'
}

group = 'az.academy'
version = '1.0.0'

java {
    toolchain { languageVersion = JavaLanguageVersion.of(21) }
}

repositories {
    mavenCentral()
}

dependencies {
    implementation 'com.fasterxml.jackson.core:jackson-databind:2.17.2'
    testImplementation 'org.junit.jupiter:junit-jupiter:5.11.0'
}

application {
    mainClass = 'az.academy.contacts.App'
}

test {
    useJUnitPlatform()
}
```

```bash
./gradlew build      # compile + test + package
./gradlew test
./gradlew run
./gradlew clean
```

## 4. Maven (same idea, XML)

```xml
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.17.2</version>
</dependency>
```
```bash
mvn clean package
mvn test
```
Coordinates `groupId:artifactId:version` identify every library on **Maven Central**.

## 5. Clean code essentials

### Names
```java
int d;                         // ❌
int daysSinceLastLogin;        // ✅
List<Customer> list;           // ❌
List<Customer> vipCustomers;   // ✅
```

### Small functions, one job
```java
// ❌ processOrder() validates, calculates, saves, sends email: 120 lines
// ✅
void placeOrder(Order order) {
    validator.validate(order);
    double total = pricing.calculate(order);
    repository.save(order.withTotal(total));
    notifier.orderPlaced(order);
}
```

### No magic numbers
```java
if (age > 18) ...                         // ❌
private static final int ADULT_AGE = 18;  // ✅
```

### Early return instead of deep nesting
```java
if (order == null) return;
if (!order.isPaid()) return;
ship(order);
```

### Comments explain **why**, code explains **what**
```java
// Bank requires 2 business days before releasing funds (regulation X)
LocalDate releaseDate = addBusinessDays(today, 2);
```

## 6. SOLID in one table

| Letter | Principle | In one sentence |
|---|---|---|
| S | Single Responsibility | a class has one reason to change |
| O | Open/Closed | extend with new classes, don't edit old ones |
| L | Liskov Substitution | subclasses must work wherever the parent works |
| I | Interface Segregation | small focused interfaces |
| D | Dependency Inversion | depend on interfaces, inject implementations |

## 7. Code review checklist

- [ ] Does it work and is it tested?
- [ ] Are names clear?
- [ ] Any duplicated code?
- [ ] Methods short and focused?
- [ ] Errors handled with good messages?
- [ ] No secrets, no commented-out code, no debug prints?
