> **Goal:** avoid NullPointerException and model "maybe absent" values with `Optional`.
> **Duration:** 90 min

## 1. The billion-dollar mistake

Tony Hoare, inventor of `null`, called it his "billion-dollar mistake". `NullPointerException` is the most common Java error.

```java
Customer c = repository.findByPhone("+994501234567");   // may return null
System.out.println(c.getName().toUpperCase());          // 💥 NPE
```

## 2. Defensive basics

```java
if (c != null && c.getName() != null) { ... }

Objects.requireNonNull(name, "name must not be null");   // fail fast in constructors
Objects.equals(a, b);                                    // null-safe equals
Objects.requireNonNullElse(nickname, "Guest");
"constant".equals(variable);                             // null-safe string compare
```

## 3. Optional

`Optional<T>` is a container that **may or may not** hold a value. It makes "absence" visible in the method signature.

```java
public Optional<Customer> findByPhone(String phone) {
    return customers.stream().filter(c -> c.phone().equals(phone)).findFirst();
}
```

### Creating
```java
Optional.of(value);          // value must not be null
Optional.ofNullable(value);  // may be null
Optional.empty();
```

### Using: avoid `get()`!
```java
Optional<Customer> customer = repo.findByPhone(phone);

customer.isPresent();                          // boolean
customer.isEmpty();
customer.ifPresent(c -> sendSms(c));
customer.ifPresentOrElse(c -> greet(c), () -> System.out.println("Not found"));

String name = customer.map(Customer::name).orElse("Unknown");
Customer c = customer.orElseThrow(() -> new CustomerNotFoundException(phone));
Customer c2 = customer.orElseGet(() -> createGuest());

customer.filter(Customer::isVip).map(Customer::email).ifPresent(this::sendOffer);
```

### `orElse` vs `orElseGet`
```java
opt.orElse(createDefault());        // createDefault() runs ALWAYS
opt.orElseGet(() -> createDefault()); // runs only if empty ✅ for expensive defaults
```

### Chaining with flatMap
```java
Optional<String> city = findCustomer(id)
        .flatMap(Customer::address)     // address() returns Optional<Address>
        .map(Address::city);
```

## 4. Where to use Optional

| ✅ Use | ❌ Don't use |
|---|---|
| return type of find methods | fields of a class |
| | method parameters |
| | collections (`Optional<List>`): return an empty list instead |
| | in place of every null check |

## 5. Step by step: refactoring a repository

Before:
```java
public Book findById(int id) {
    return books.get(id);           // null if absent
}
// caller
Book b = repo.findById(5);
if (b == null) { System.out.println("Not found"); } else { ... }
```
After:
```java
public Optional<Book> findById(int id) {
    return Optional.ofNullable(books.get(id));
}
// caller
Book b = repo.findById(5).orElseThrow(() -> new ItemNotFoundException(5));
String title = repo.findById(5).map(Book::getTitle).orElse("-");
```

## 6. Common mistakes

- ❌ `optional.get()` without check → `NoSuchElementException` (same problem as NPE).
- ❌ `if (opt.isPresent()) { x = opt.get(); }`: use `map`/`orElse`.
- ❌ Returning `null` from a method that returns `Optional`.
- ❌ `Optional.of(null)` → NPE.

## 8. Homework

Change all `find...` methods in your project to return `Optional` and update the callers to use `orElseThrow` with custom exceptions or `map/orElse`.

## 9. Self-check

1. Why is `Optional` better than returning `null`?
2. Difference between `orElse` and `orElseGet`?
3. Should a class field be `Optional`?

<details><summary>Answers</summary>

1. Absence is explicit in the type; the compiler and the reader see that the value may be missing.
2. `orElse` always evaluates its argument; `orElseGet` calls the supplier only when empty.
3. No: use it mainly for return types.

</details>
