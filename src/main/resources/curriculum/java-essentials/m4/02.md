> **Goal:** process collections declaratively with the Stream API.
> **Duration:** 90 min

## 1. Imperative vs declarative

```java
// imperative: HOW
List<String> result = new ArrayList<>();
for (Product p : products) {
    if (p.stock() > 0) {
        result.add(p.name().toUpperCase());
    }
}
Collections.sort(result);

// declarative with streams: WHAT
List<String> result = products.stream()
        .filter(p -> p.stock() > 0)
        .map(p -> p.name().toUpperCase())
        .sorted()
        .toList();
```

## 2. Stream pipeline

```
source  →  intermediate operations (0..n)  →  terminal operation (1)
list.stream()   filter / map / sorted ...       toList / count / forEach ...
```

- Streams **do not modify** the source.
- Intermediate operations are **lazy**: nothing runs until a terminal operation.
- A stream can be used **once**.

## 3. Creating streams

```java
list.stream();
Arrays.stream(array);
Stream.of("a", "b", "c");
IntStream.range(0, 10);           // 0..9
IntStream.rangeClosed(1, 5);      // 1..5
Stream.iterate(1, x -> x * 2).limit(10);
Files.lines(Path.of("data.csv")); // lines of a file
```

## 4. Intermediate operations

| Operation | Does |
|---|---|
| `filter(Predicate)` | keep matching elements |
| `map(Function)` | transform each element |
| `sorted()` / `sorted(Comparator)` | sort |
| `distinct()` | remove duplicates |
| `limit(n)` / `skip(n)` | take / skip |
| `peek(Consumer)` | debug (look at elements) |

## 5. Terminal operations

```java
.toList()                       // Java 16+, unmodifiable
.collect(Collectors.toList())   // older style
.count()
.forEach(System.out::println)
.anyMatch(p -> p.price() > 1000)
.allMatch(p -> p.stock() >= 0)
.noneMatch(p -> p.name().isBlank())
.findFirst()                    // Optional<T>
.min(Comparator.comparing(Product::price))
.max(...)
```

## 6. Step by step: product queries

```java
record Product(String name, String category, double price, int stock) { }

List<Product> products = List.of(
    new Product("MacBook Air", "Laptop", 2400, 5),
    new Product("ThinkPad", "Laptop", 1900, 0),
    new Product("Logitech MX", "Mouse", 180, 25),
    new Product("Dell 27\"", "Monitor", 650, 8),
    new Product("Razer", "Mouse", 120, 3));

// 1. names of laptops in stock
products.stream()
        .filter(p -> p.category().equals("Laptop"))
        .filter(p -> p.stock() > 0)
        .map(Product::name)
        .toList();                                   // [MacBook Air]

// 2. the 3 cheapest products
products.stream()
        .sorted(Comparator.comparingDouble(Product::price))
        .limit(3)
        .toList();

// 3. is anything out of stock?
boolean outOfStock = products.stream().anyMatch(p -> p.stock() == 0);   // true

// 4. most expensive product
Product top = products.stream()
        .max(Comparator.comparingDouble(Product::price))
        .orElseThrow();

// 5. distinct categories sorted
products.stream().map(Product::category).distinct().sorted().toList();
```

## 7. Laziness in action

```java
Stream.of("a", "b", "c")
      .peek(s -> System.out.println("processing " + s))
      .filter(s -> s.equals("b"))
      .findFirst();
// prints only "processing a", "processing b": it stops early!
```

## 8. Common mistakes

- ❌ Reusing a stream → `IllegalStateException`.
- ❌ Forgetting the terminal operation (nothing happens).
- ❌ Side effects inside `map`/`filter` (modifying external lists).
- ❌ `forEach` + `add` to an external list instead of `toList()`.

1. What is the difference between intermediate and terminal operations?
2. Does `stream().filter(...)` change the original list?
3. Why does `findFirst` return `Optional`?

<details><summary>Answers</summary>

1. Intermediate operations return a new stream and are lazy; terminal ones produce a result and trigger processing.
2. No.
3. Because the stream may be empty: there may be no first element.
